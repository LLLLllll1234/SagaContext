## G3 Codex 宿主探针

探针使用临时 Git 仓库和仓库级 `.codex/hooks.json`，不读取现有 transcript、不修改用户 hook 配置。记录器只保存 payload 字段名、字段是否存在以及非敏感枚举，不保存 prompt、工具输入输出正文、真实 ID 或路径。

当前证据分三层，不能互相替代：

- **发行版静态能力：** `codex-cli 0.150.0-alpha.8` 的 `codex features list` 返回 `hooks stable true`。
- **固定源码快照：** 本地 Codex `728cb12fe5794b0c3a8e776fb4994b1650b973a8` 声明 12 类 hook 事件，并含工具调用前后的运行路径。这能反驳“Codex 一律只有四类事件”，但不证明当前 CLI 已实际触发。
- **当前运行时：** `codex exec --json --ephemeral --ignore-user-config` 在首个事件样本出现前因模型认证失败而终止。`SessionStart`、`UserPromptSubmit`、`PreToolUse`、`PostToolUse`、`Stop`、`SessionEnd` 均为 `not_observed`；注入、transcript 字段、超时和异常退出恢复均未验证。

受阻结果保存在 `tests/fixtures/hosts/codex-cli-0.150.0-alpha.8.json`。fixture 只保留 `model_authentication_failed` 枚举，不保存认证材料、服务端点或原始错误文本。认证可用后应重新运行：

```bash
.venv/bin/python scripts/probe_codex_host.py \
  --output tests/fixtures/hosts/codex-cli-0.150.0-alpha.8.json
```

只有 fixture 中至少出现实际事件 payload，且注入、结束、超时与恢复行为分别有观测记录后，G3 才能改为通过。
