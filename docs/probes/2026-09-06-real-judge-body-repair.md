## 已核实的失败原因

历史证据：[v2 语义验收](2026-09-06-real-judge-semantic-acceptance.md)及其[三轮原始结果](../../artifacts/real-judge/20260906T065104Z-db2e433e/replay.jsonl)。

| 问题 | 证据与根因 | 本次处理 |
|---|---|---|
| refine 丢失旧字段 | 2 次只返回 `applies_when`，缺少 anchor 中的 `symptom`、`fix`。旧提示词没有明确区分完整正文与补丁；转换器原样传递 payload，而 Ledger 保存的是完整新修订 | 提示词明确完整正文；转换前检查 refine 包含 anchor 全部顶层字段，缺失则整批阻断 |
| format 枚举扩写 | 6 次输出 `JSON`、`concise JSON results` 或 `prose summaries`。旧提示词要求保留枚举，却没有列出合法值；`json_object` 与开放的 `Delta.fields` 不约束业务枚举 | 明确 `json/prose` 小写枚举及自然语言到枚举的映射，保持原评分器严格判定 |
| 60 秒超时 | 1 次请求约 60.21 秒后失败；同例另外两轮成功。旧产物没有记录 HTTP 超时阶段，无法区分连接、读取、中转排队或模型计算 | 将 HTTPX 的 connect/read/write/pool/unknown 阶段传递至 trace、JSONL 和报告；继续每 observation 一次请求 |

这里的 refine 问题不只影响分数：旧输出若进入 Ledger，会把未返回的旧字段从新修订正文中移除。新检查只保证顶层字段未遗漏，不证明字段值或嵌套正文在语义上正确。

`read` 超时也只能定位客户端等待读取阶段，不能据此断言是中转或模型故障。历史超时原因仍为未定位，不能用本地异常测试补写其结论。

## 实现与版本

- `openai-judge-prompt-v3`：明确 confirm 复制正文、refine 保留旧事实并补全、supersede 替换冲突值；列出 `taste.format` 的合法枚举。传给模型的内容仍只有 anchors、candidates 和 summary，不含标注或可接受答案。
- `delta-to-proposal-v2`：不完整 refine 抛出不可重试的 `judge_conversion_error`，不自动补齐或修饰模型输出。已解析但转换失败的原始 Delta 和 digest 保留在 trace 中；失败不会被计为成功或 `no_change`。
- `delta-v2` 与 `response_format=json_object` 沿用已验证的接口。枚举指令属于提示约束，尚无 provider 约束解码保证。严格 JSON Schema 需要单独验证中转能力，不能直接假定支持。
- 报告增加 prompt/schema/converter 版本和逐次调用失败表；超时只记录固定阶段枚举，不保存异常消息、请求 URL 或认证内容。

数据集保持 `real-judge-v2`，digest 仍为 `254c47f4554c3d506e419200203e96f1f6c7e05386c370d7cab7e614e9b6cfce`。`body-schema-v1`、`body-normalizer-v1`、全部预期答案、门槛和历史 artifact 未修改。

新保护可能把此前可转换的错误正文变为转换失败，因此后续报告必须同时查看调用状态和适用分母。不能用排除失败后的 body 比例宣称语义质量提升；任一调用失败仍阻断正式验收。
