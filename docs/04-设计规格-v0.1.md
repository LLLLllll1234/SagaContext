## 0. 一页总览

SagaContext 是叠在 OpenViking 之上的**开发者个性化记忆层**，让 Codex 与 Claude Code 在同一个人的所有项目里"越用越懂你、且真的照做"。

```
Codex / Claude Code ──(上游插件 hooks)──► OpenViking sidecar
        │                                       ▲   ▲
        │ transcript / tool 轨迹                 │   │ 自定义 memory type (yaml)
        ▼                                       │   │ viking://user/{uid}/memories/dev/**
[sagactl daemon]                                │   │
  ├─ Correction Miner ── 纠正/约定/口味 ─────────┘   │
  ├─ Evolution Reconciler ── 冲突/取代/确认队列 ─────┘
  ├─ Recall Policy ── 用户×类型×scope 权重 (M3)
  ├─ Compliance Compiler ── convention → 可检查规则 (M2)
  └─ Eval Runner ── DevPref-Bench
```

四个不可让步的边界：
1. **不修改 OpenViking 服务端代码**；只用 `memory.custom_templates_dir`、HTTP/MCP API、上游插件的 hook 事件。
2. **一切个性化记忆有 grounding**：每条记忆都能回到产生它的原始 turn。
3. **冲突不静默覆盖**：偏好反转进待确认队列，用户不确认则两版并存并标注。
4. **数字全部 `[TARGET]`**，直到 Eval Runner 跑出来。

## 1. 术语

| 术语 | 含义 |
|---|---|
| **纠正 (correction)** | 用户对 Agent 产出的否定/修改，含显式（"别用 any"）与隐式（撤销 Agent 改动后手动改回） |
| **约定 (convention)** | 可判定的规则，来源可以是纠正、用户陈述、或从多次纠正归纳；形如"在 scope S 内，条件 C 时，应/不应 X" |
| **口味 (taste)** | 不可硬判定的倾向：解释详略、评审严格度、风险偏好、工具习惯 |
| **scope** | 记忆生效范围：`global` / `repo:<git_root_hash>` / `glob:<repo>:<pattern>` |
| **grounding** | 记忆的证据：`(source_agent, session_id, turn_range, tool_call_ids?, git_root, git_rev)` |
| **演化状态** | `active` / `superseded` / `pending_confirm` / `retired` |

## 2. 开发者记忆 Schema（P1）

### 2.1 落地方式

OpenViking 通过 `memory.custom_templates_dir` 加载自定义类型（`memory_type_registry.py:42-90`，`replace=True` 可覆盖同名内置类型）。SagaContext 提供一个模板目录 `templates/memory/`，安装时写入 `ov.conf`：

```toml
[memory]
custom_templates_dir = "~/.sagacontext/templates/memory"
```

### 2.2 上游 schema 能力与约束（源码核对）

| 能力 | 事实 | 对设计的影响 |
|---|---|---|
| 字段类型 | `FieldType` 仅 `string / int64 / float32 / bool`（`merge_op/base.py:14-20`） | `evidence[]`、`scope` 列表等必须**序列化为 string**（JSON 或 Markdown 列表） |
| 字段合并 | `patch`（SEARCH/REPLACE）/ `replace` / `sum` / `immutable` | `evidence_count` 用 `sum`；`content` 用 `patch`；标识字段 `immutable` |
| 类型级模式 | `operation_mode: upsert \| add_only`；`stage: user \| agent`；`agent_only` | correction 用 `add_only`（纠正是事件，不合并）；convention/taste 用 `upsert` |
| 目录与文件名 | `directory` 用 `{{ user_space }}`；`filename_template` 可含子路径与抽取字段（preferences 用 `{{ user }}/{{ topic }}.md`） | **scope 编进路径**：`{{ scope_key }}/{{ topic }}.md` |
| supersedes | 仅 experiences 类型由 `agent_experience_context_provider` 处理，通用类型**没有** | 演化逻辑在 SagaContext 侧（Evolution Reconciler）做，schema 里只留字段 |
| 抽取输入 | 会话 commit 后异步抽取；上游 prompt 明确"omit supporting evidence" | Correction Miner **先于**上游抽取产出结构化候选，把 grounding 作为字段写入，而非依赖上游抽取保留 |

### 2.3 类型定义

四个类型，全部 `stage: user`，`directory: viking://user/{{ user_space }}/memories/dev`。

#### `dev_convention`（upsert）

| 字段 | 类型 | merge_op | 说明 |
|---|---|---|---|
| `topic` | string | immutable | 唯一键，snake_case ≤5 词，如 `ts_no_any`、`tests_location`、`commit_message_style` |
| `scope_key` | string | immutable | `global` / `repo-<8hex>` / `glob-<8hex>-<slug>`；进路径 |
| `scope_pattern` | string | replace | glob 时的原始 pattern；global/repo 为空 |
| `rule` | string | patch | **可判定**的一句话规则，祈使句，含条件；例："在 `src/**/*.ts` 中不得使用 `any`；确需时写 `unknown` 并加类型守卫" |
| `rationale` | string | patch | 用户给出的理由（若有），一句 |
| `check_hint` | string | replace | 可选：如何机械检查（`eslint rule`/`grep`/`path constraint`/`none`），供 M2 编译 |
| `confidence` | float32 | replace | 0–1，由 Reconciler 维护（见 §3.3） |
| `evidence_count` | int64 | sum | 支持该规则的纠正/确认次数 |
| `contra_count` | int64 | sum | 与之矛盾的观测次数 |
| `valid_from` | string | replace | ISO 日期 |
| `superseded_by` | string | replace | 取代者 topic；非空即 `superseded` |
| `status` | string | replace | `active / superseded / pending_confirm / retired` |
| `last_confirmed` | string | replace | 最近一次用户确认或遵守观测的日期 |
| `evidence` | string | patch | JSON 数组（string 承载），每项 = grounding（§2.4），最多保留 10 条，最旧淘汰 |

#### `dev_correction`（add_only，事件型）

| 字段 | 类型 | merge_op | 说明 |
|---|---|---|---|
| `correction_id` | string | immutable | `<session_id>-<turn>` |
| `scope_key` | string | immutable | 发生时的 scope |
| `kind` | string | immutable | `explicit_negation` / `explicit_instruction` / `revert_and_redo` / `edit_after_agent` |
| `agent_did` | string | immutable | Agent 原产出摘要（≤200 字）|
| `user_wanted` | string | immutable | 用户要的（≤200 字）|
| `derived_topic` | string | replace | Reconciler 归并到的 convention/taste topic；空 = 未归并 |
| `grounding` | string | immutable | JSON（§2.4） |
| `occurred_at` | string | immutable | ISO |

设计意图：correction 是**不可变事实流**，convention/taste 是从它归纳出的**可变状态**。这与 PGMem "persona 信号绑定 grounding event" 和 PROJECTMEM "append-only 事件日志 + 投影" 同构，但承载在 viking:// 上。

#### `dev_taste`（upsert）

| 字段 | 类型 | merge_op | 说明 |
|---|---|---|---|
| `dimension` | string | immutable | 固定枚举：`explanation_depth` / `review_strictness` / `risk_tolerance` / `tool_habit` / `communication_style` / `test_appetite` |
| `scope_key` | string | immutable | |
| `content` | string | patch | Markdown bullets，每条一个可复用倾向 |
| `confidence` / `evidence_count` / `contra_count` / `valid_from` / `status` / `last_confirmed` / `evidence` | 同 convention | |

#### `dev_profile`（upsert，覆盖内置 `profile`）

用 `replace=True` 机制覆盖上游消费级 profile 模板，字段只留：`stack`（语言/框架，含"as of"）、`experience_level`、`roles`、`working_hours_tz`、`explanation_language`。删除出生日期/性别/恋爱状态等消费级字段。

### 2.4 grounding 格式

```json
{
  "source_agent": "claude-code | codex",
  "session_id": "…",
  "turn_range": [12, 14],
  "tool_call_ids": ["toolu_…"],
  "git_root": "/abs/path",
  "git_root_hash": "8hex",
  "git_rev": "abc1234",
  "files": ["src/foo.ts"],
  "quote": "≤160 字原话（已脱敏）"
}
```

`git_root_hash = sha1(realpath(git_root))[:8]`；同一 repo 在两台机器路径不同时，可选用 `sha1(first_commit_hash)` 作为稳定键（配置项）。

### 2.5 scope 解析

召回时给定当前 `cwd`，生效 scope 集合 = `{global} ∪ {repo-<h>} ∪ {glob-<h>-* 中 pattern 匹配当前编辑文件者}`。优先级 glob > repo > global；同 topic 多 scope 并存时取最具体者，其余标注 "被 X 覆盖"。

## 3. Correction Miner 与 Evolution Reconciler（P1/P2）

### 3.1 触发与输入

复用上游插件事件（Claude Code 9 hooks；Codex 4 hooks）：

| 事件 | 用途 |
|---|---|
| `UserPromptSubmit` | 显式纠正检测（在线，轻量规则）；把当前 prompt 与上一轮 Agent 产出配对 |
| `PostToolUse`（Claude Code 有；Codex 无） | 记录 Agent 的 Edit/Write 目标文件与 diff hash，供 revert 检测 |
| `Stop` / `SessionEnd` | 离线：Miner 全量扫本会话 transcript，产出 correction 候选并写入 |
| `PreCompact` | 在压缩前抢救未处理的候选 |

Codex 无 `PostToolUse`：revert 检测改为在 `Stop` 时对比 transcript 中 Agent 声明修改的文件与工作树 `git diff`。

### 3.2 纠正识别（分层，宁缺毋滥）

| 层 | 方法 | 输出 |
|---|---|---|
| L0 规则 | 否定模式（中英）："不要/别/不用/never/don't/stop using X"、"改成/换成/use Y instead"、"以后都/always/from now on" | `explicit_negation` / `explicit_instruction` 候选，置信 0.6 |
| L1 结构 | Agent 上一轮 Edit 的文件在用户下一条 prompt 前被用户手动改回（PostToolUse 记录的 diff hash vs 工作树） | `revert_and_redo` 候选，置信 0.7 |
| L2 LLM 判定 | 对 L0/L1 候选 + 前后 2 轮上下文，让本地/配置模型输出 `{is_correction, kind, agent_did, user_wanted, generalizable: bool, proposed_topic, proposed_scope, proposed_rule}` | 过滤一次性指令（"这次先不加测试"），只保留 `generalizable=true` |

**写入策略（借鉴 Mem0 coding 指南的保守写入）：** correction 全部写入（add_only，便宜且可审计）；convention/taste 只在 (a) 用户明确用了"以后都/always"类词，或 (b) 同 topic 同 scope 的 correction ≥2 次时才创建。

### 3.3 演化状态机

```
                 新 correction (topic T, scope S)
                          │
        ┌─────────────────┼──────────────────┐
        ▼                 ▼                  ▼
   无 active T      有 active T 且一致    有 active T 且矛盾
        │                 │                  │
  evidence_count≥2?  evidence_count+=1   contra_count+=1
        │            confidence↑          │
        ▼            last_confirmed       ▼
   创建 active T                    "以后都"类强信号？
                                     ├─ 是 → 旧 T.status=superseded, superseded_by=T'
                                     │       新 T' active, valid_from=now
                                     └─ 否 → T.status=pending_confirm
                                             进待确认队列（§3.4）
```

- `confidence = clamp(0.5 + 0.1·evidence_count − 0.2·contra_count − decay)`，`decay = 0.05 × 距 last_confirmed 的月数`，下限 0.1；`< 0.3` 且 90 天无确认 → `retired`。
- 非单调：反转后再反转回来，不复活旧记录，创建新记录并让 `evidence` 引用两次反转，便于回答"你之前改过两次"。
- 遵守观测（M2 引入）：Agent 产出通过了 T 的检查且用户未纠正 → `last_confirmed` 刷新，不加 evidence_count（避免自证）。

### 3.4 待确认队列

`~/.sagacontext/pending.jsonl`，每项含冲突双方 + grounding。呈现方式：
- `sagactl review`：CLI 逐条确认（keep old / take new / both with scopes / drop）。
- 下次 SessionStart 注入一行提示（≤80 token）："有 N 条偏好冲突待确认，`sagactl review`"。不在 prompt 里展开冲突内容。

## 4. 注入与召回策略（P1 基线 → P3 学习）

### 4.1 M1 基线策略（无学习）

- **SessionStart**：注入 `dev_profile` + 当前 scope 集合内 `status=active` 且 `confidence≥0.5` 的 convention（按 confidence 降序，上限 12 条）+ taste（每 dimension 取最具体 scope 一条）。格式复用上游 `<memory uri type score detail>` 信封（`render.py`），加 `scope` 与 `confidence` 属性。预算 ≤1500 token。
- **UserPromptSubmit**：不额外召回 convention（已在开头）；只对 `dev_correction` 做语义召回 top-3 作为"上次你在类似情况下纠正过"提示，仅当相似度 ≥0.6。
- **排除**：`pending_confirm` 不注入；`superseded` 不注入；跨 repo 的 `repo-*` 不注入（误注入率是核心指标之一）。

### 4.2 M3 学习策略（P3）

- 信号：`record_used`（上游 `/sessions/{id}/used`，正）、最终回答/产出引用了记忆 URI（正）、注入但本轮 Agent 产出违反（负，来自 M2 检查）、注入后用户纠正了同 topic（强负）。
- 参数：每 (用户, 类型, scope 层级) 一个注入权重 `w ∈ [0,2]`，初值 1；在线更新 `w ← w + η·(reward)`，η=0.05，每周衰减向 1 回归 10%。
- 决策：注入排序分 = `confidence × w × scope_specificity(glob 1.2 / repo 1.0 / global 0.8)`；预算内贪心。
- 可解释：每次注入写 trace（§7），含每条的四个因子。
- 与上游 hotness 的关系：上游 `hotness_alpha` 保持默认；SagaContext 的 w 作用在自己的注入排序上，不改上游检索分。

## 5. Compliance Layer（P4，M2）

### 5.1 编译目标

只编译 `dev_convention` 且 `check_hint ≠ none` 且 `confidence ≥ 0.6` 的规则。三种执行器：

| `check_hint` | 执行方式 | 例 |
|---|---|---|
| `path` | PreToolUse(Edit/Write) 拦截：目标路径不满足约束 → 返回 `decision: block` + 理由 + 规则 URI | "测试文件必须在 `tests/`" |
| `pattern` | PreToolUse(Edit/Write)：对 `new_string` 跑正则/AST 简查 → block 或 warn | "不得 `: any`"、"禁止 `console.log` 进 `src/`" |
| `command` | Stop 前对本轮修改文件跑指定命令（如 `eslint --rule …`），失败 → 注入一条 systemMessage 让 Agent 修 | "commit 前 `ruff check` 必须过" |

Codex 无 PreToolUse：`path`/`pattern` 退化为 `Stop` 时检查 + 下一轮注入违规提示（软强制）。

### 5.2 强制策略

- 默认 `warn`（注入违规说明，不 block）；用户可对单条规则设 `block`。
- 每次违规写 `dev_correction(kind=compliance_violation)`——**不**计入 evidence_count（自证禁止），但计入 M3 的负信号。
- 用户连续 3 次对同一 block 说"这次就这样" → 自动降级为 warn 并进待确认队列。

### 5.3 与 TRACE/tellonce 的差异（写进文档以防被问）

tellonce 是单会话内、Claude Code 专用、规则来自当轮纠正；SagaContext 的规则来自跨会话跨宿主的持久记忆，带 scope 与演化，且强制执行结果反哺记忆置信度。

## 6. DevPref-Bench（评测，M1 起）

### 6.1 数据

两来源，都标注 scope 与时间：
1. **真实回放**：用户自己的 Codex / Claude Code transcript，Miner 抽出的 correction 经人工确认后作 GT。`[TARGET]` ≥ 60 条纠正、≥ 3 个 repo。
2. **合成演化**：仿 PERMA 事件驱动——为每条 GT 偏好生成 T1 建立 / T2 反转 / T3 隐式使用 的三段会话；再为 repo 隔离生成"repo A 约定，repo B 同类任务"对。

### 6.2 任务与指标

| 指标 | 定义 | 对应层 |
|---|---|---|
| **遵守率** | 后续任务不提及偏好时，产出符合 active 规则的比例（TRACE 口径 = 1 − violation rate） | P1/P4 |
| **演化正确率** | T2 反转后，T3 使用新版的比例 | P2 |
| **误注入率** | repo B 任务中注入了 repo A 专属约定的比例 | P1 scope |
| **Turn≤2 恢复率** | 用户纠正后 2 轮内 Agent 改正的比例（PERMA 口径） | P2/P4 |
| **重复纠正次数** | 真实使用日志中同 topic 被再次纠正的次数/周 | 全部 |
| **注入 token / 会话** | | 效率 |
| **确认队列负担** | 每周待确认条数、用户处理时长 | P2 可用性 |

### 6.3 基线

`NoMemory` / `Claude Code Auto Memory` / `OpenViking 原生 preferences` / `Mem0(user scope)` / `tellonce`（仅遵守率）/ `SagaContext-M1`(文本注入) / `-M2`(+强制) / `-M3`(+学习)。

### 6.4 控制变量

模型与版本、OpenViking commit、模板版本、scope 解析规则、confidence 阈值、随机种子、是否含 revert 检测。

## 7. 组件与接口

### 7.1 进程

- `sagactl daemon`：本机 `127.0.0.1:37780`，AsyncIO；上游插件 hook 脚本通过一个薄 shim（≤50 行，Apache-2.0 自写，不复制上游 AGPL `.mjs`）把事件 POST 过来；fail-open，超时 800ms。
- 依赖：OpenViking HTTP（`/search/find`、`/content/read`、`/content/write`、`/sessions/*`）；MCP 不必需。

### 7.2 内部 API

| 方法 | 用途 |
|---|---|
| `POST /events` | hook 事件入口（session_start / prompt / post_tool / stop / session_end / pre_compact） |
| `POST /recall` | 返回本轮注入块 + trace_id |
| `POST /check` | Compliance 检查（M2） |
| `GET /pending` / `POST /pending/{id}/resolve` | 待确认队列 |
| `GET /trace/{id}` | 注入分解 |

### 7.3 CLI

`sagactl doctor | status | review | show <topic> | explain <trace_id> | forget <topic|scope|session> | export | bench run <config>`

### 7.4 Trace（JSONL）

每次 recall 一行：`{trace_id, session_id, source_agent, scope_set, injected:[{uri, type, scope, confidence, w, specificity, score, tokens}], excluded:[{uri, reason}], budget, latency_ms}`。

### 7.5 数据位置

- 记忆本体：OpenViking `viking://user/{uid}/memories/dev/**`
- 本地状态：`~/.sagacontext/{pending.jsonl, weights.json, traces/, bench/}`
- 删除：`forget` 同时删 OpenViking 文件与本地状态；`reset` 清空 `memories/dev`。

## 8. 隐私、许可证、故障

- 纠正原话 `quote` 写入前脱敏（复用上游插件的 secret 模式 + 自有规则）；`quote` 上限 160 字。
- 记忆正文视为不可信；注入信封防伪造（复用 `render.py` 的转义思路）。
- 许可证：OpenViking AGPL 独立进程；SagaContext Apache-2.0；hook shim 自写；不 vendoring 上游 `.mjs`。
- 故障：OpenViking 不可用 → 不注入、correction 候选进本地 pending queue 重试（**Codex 侧尤其需要，上游 Codex 插件无磁盘队列**）；LLM 判定失败 → 只保留 L0/L1 候选、不创建 convention；Compliance 执行器异常 → 视为通过并记 trace。
