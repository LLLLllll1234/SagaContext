Codex：`SessionStart(clear|startup|resume) / UserPromptSubmit / Stop / SessionEnd` 四项，命令同上换 `codex`。宿主侧 timeout 故意设得比 shim 的 800ms 大，保证是 shim 先超时并 fail-open，而不是宿主杀进程。

**注意：** 所有写回工作都在 daemon 内异步执行，hook 只负责把事件送达；`stop / session_end / pre_compact` 立即返回空 JSON。

### 1.4 shim `bin/sagactl-hook`

```sh
#!/bin/sh
# usage: sagactl-hook <host> <event>   stdin = 宿主 hook payload(JSON)
HOST="$1"; EVENT="$2"
URL="http://127.0.0.1:${SAGACTL_PORT:-37780}/events?host=${HOST}&event=${EVENT}"
OUT=$(curl -s -m 0.8 -H 'Content-Type: application/json' --data-binary @- "$URL" 2>/dev/null)
RC=$?
if [ $RC -ne 0 ]; then
  # daemon 不在线：拉起并 fail-open
  if [ $RC -eq 7 ] && command -v sagacontext-daemon >/dev/null 2>&1; then
    nohup sagacontext-daemon >/dev/null 2>&1 &
  fi
  echo '{}'; exit 0
fi
[ -n "$OUT" ] && printf '%s\n' "$OUT" || echo '{}'
exit 0
```

`curl` 退出码 7 = 连接被拒。shim 永远 exit 0。

## 3. 事件处理时序

daemon 内每个事件的处理都包在 `asyncio.wait_for(..., recall_budget_ms)` 里；超时返回 `{}`，并记一条 warn trace。

### 3.1 `session_start`

```
1. hosts.normalize(raw) → HostEvent
2. repo_key = scope.resolve(cwd)              # §4.1，命中 repo_keys 缓存则 <1ms
3. sessions upsert (cursor_offset=0)
4. 并行：
   a. anchors = recall.session_start(repo_key, cwd)        # §4.2
   b. task = tasks.resume_candidate(repo_key, branch)      # §7
   c. pending_n = store.count_pending()
   d. flush_orphans(host)   # 上次异常退出留下的未消费 buffer → 触发一次对账（后台）
5. blocks = render(task_block?, anchors, pending_hint?)    # 预算 2000 token
6. recalled ← anchors 的 uri
7. 返回 {"hookSpecificOutput": {"hookEventName": "SessionStart", "additionalContext": blocks}}
```

### 3.2 `prompt`（UserPromptSubmit）

```
1. HostEvent（含 prompt）
2. 并行：
   a. cands = capture.l0(prompt, last_assistant_turn)      # §5.1，纯正则，<2ms
   b. reverts = capture.l1(session, cwd)                   # §5.2，比对 tool_edits vs 工作树
   c. hits = recall.prompt(prompt, repo_key, files_mentioned)   # §4.3
3. buffer ← cands + reverts
4. sessions.turn_count += 1；token_estimate += len(prompt)/3
5. 任务接续二次判定：若 session_start 给了提示且 prompt 含"继续/接着/continue" 或 sim(goal) ≥ 0.5 → sessions.task_id = 该任务
6. 返回 additionalContext（≤600 token），无命中则 {}
```

### 3.3 `pre_tool`（Claude Code，Edit/Write/MultiEdit）

```
1. path = tool.input.file_path
2. gotchas = recall.gotcha_by_path(repo_key, path)          # 本地缓存的 trigger_paths 索引，不打 OV
3. M1：有命中 → additionalContext 一行；无 → {}
   M2：叠加 compliance.check(path, new_string) → permissionDecision allow|deny + reason
```

Claude Code 的 PreToolUse 输出格式：`{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "allow"|"deny"|"ask", "permissionDecisionReason": "...", "additionalContext": "..."}}`。

### 3.4 `post_tool`（Claude Code）

```
Edit/Write/MultiEdit：tool_edits ← (path, sha256(读工作树文件), tool_call_id)
Bash：若 tool_response 非零退出 / 含 "Error|Traceback|FAILED" → buffer ← Candidate(L0, project, gotcha_fail, files=从命令解析)
返回 {}
```

### 3.5 `stop`

```
1. sessions.last_event_at = now
2. 判定是否写回：token_estimate ≥ 20000 或 turn_count ≥ 10 或 buffer 未消费 ≥ 20
3. 若是 → asyncio.create_task(reconcile.run(session, reason="stop"))，并重置计数
4. 立即返回 {}
```

### 3.6 `session_end` / `pre_compact`

```
1. create_task(reconcile.run(session, reason=event))     # 无条件
2. session_end：sessions.ended = 1；tasks.touch(session.task_id)
3. 返回 {}
```

`pre_compact` 后宿主会压缩上下文，但 transcript 文件不变，所以我们的游标不受影响；只是把这一刻当作一次写回机会。

### 3.7 Codex 差异

- 没有 `pre_tool/post_tool`：gotcha 候选与 revert 检测都在 `reconcile.run` 内对 transcript 增量做（§5.2 Codex 分支）。
- `SessionStart` matcher 含 `resume`：resume 时不重置游标，从 `sessions.cursor_offset` 继续。

## 4. 召回实现

### 4.1 scope 解析（`recall/scope.py`）

```python
def resolve(cwd: Path) -> RepoInfo:
    rp = cwd.resolve()
    if hit := store.repo_keys.get(rp): return hit
    git_root = run("git -C {cwd} rev-parse --show-toplevel")          # 失败 → 非 git
    if git_root:
        first = run("git -C {root} rev-list --max-parents=0 HEAD").splitlines()
        key = sha1(first[0])[:8] if first else sha1(str(git_root))[:8]
        kind = "first_commit" if first else "path"
    else:
        key, kind, git_root = sha1(str(rp))[:8], "path", None
    branch = run("git -C {root} rev-parse --abbrev-ref HEAD") if git_root else None
    store.repo_keys.put(rp, key, kind, git_root)
    return RepoInfo(key, kind, git_root, branch)
```

`git` 子进程总耗时 < 30ms，且只在首次进入某目录时发生。

### 4.2 `session_start` 召回（`recall/policy.py`）

三次并发 `find`（§8.1），全部限定 `target_uri` 在 `dev_root` 下：

| 目标 | `target_uri` | `query` | `limit` | 后处理 |
|---|---|---|---|---|
| L2 convention | `{dev}/convention/global/`、`{dev}/convention/repo-<k>/`、`{dev}/convention/glob-<k>-*/` | 空串（列表模式，取全部） | 100 | 解析 MEMORY_FIELDS；过滤 `status=active ∧ confidence≥0.5`；同 topic 多 scope 取 specificity 最高；按 confidence 降序取 12 |
| L1 profile+taste | `{dev}/profile.md`、`{dev}/taste/{global,repo-<k>}/` | 空串 | 20 | 每 dimension 取最具体 scope 一条 |
| L3 gotcha | `{dev}/project/repo-<k>/gotcha/` | 空串 | 50 | 只留 `trigger_paths` 与 cwd / 最近修改文件（`git diff --name-only HEAD~3`）glob 命中的，≤3 条；同时把全部 gotcha 的 `trigger_paths` 写进内存索引供 `pre_tool` 用 |

`find` 返回带 `read_content=true` 时直接拿正文，省一轮 `content/read`。**跨 repo 不召回**由 `target_uri` 保证，不靠事后过滤。

### 4.3 `prompt` 召回

两次并发 `find`：
- `target_uri=[{dev}/project/repo-<k>/decision/, {dev}/project/repo-<k>/map/, {dev}/project/repo-<k>/gotcha/]`，`query=prompt`，`limit=3`，`score_threshold=0.5`。
- `target_uri=[{dev}/correction/global/, {dev}/correction/repo-<k>/]`，`query=prompt`，`limit=3`，`score_threshold=0.6`。

结果去掉本会话已注入过的 URI（`recalled` 表），剩余的记入 `recalled`。

### 4.4 预算与渲染（`recall/render.py`）

```python
def render(items: list[MemoryRecord], budget: int) -> str:
    out, used = [], 0
    for it in sorted(items, key=rank_key):            # M1: confidence×specificity；M3: ×w
        block = envelope(it)                           # 见下
        t = count_tokens(block)
        if used + t > budget: break
        out.append(block); used += t
    return "\n".join(out)
```

信封：

```
<memory uri="viking://~/memories/dev/convention/repo-3f9a1c2e/ts_no_any.md" type="dev_convention" layer="preference" scope="repo" confidence="0.70">
在 `src/**/*.ts` 中不得使用 `any`；确需时写 `unknown` 并加类型守卫。
</memory>
```

正文字段映射：convention→`rule`；taste→`content`；decision→`decision`+一行`rationale`；map→`responsibility`+`paths`；gotcha→`symptom`→`fix`；task→`goal / open / next`。正文中的 `<` `>` 转义为 `&lt;` `&gt;`（TD-16）。

### 4.5 `record_used`

注入后不立刻上报。`stop` 时对本会话 transcript 增量做一次扫描：assistant 文本中出现了某已注入 URI 的 `topic/key` 或引用了其 `files` 中的路径 → 视为使用，`POST /sessions/{ov_session_id}/used {contexts:[uri]}`。`ov_session_id` 取上游插件对该宿主会话使用的 id（上游插件用宿主 `session_id` 派生；若无法确定则跳过，不阻塞）。这是 M3 的正信号来源，M1 只记录。

### 5.1 L0 规则（`capture/rules_l0.py`）

```yaml

- id: en_negation
  layer: preference; kind: explicit_negation; confidence: 0.6; needs_prev_assistant: true

- id: zh_decision
  layer: project; kind: decision_stmt; confidence: 0.6
  regex: '(?:我们决定|决定|改用|换成|选择?了?|统一用)\s*(?P<what>.{2,60})(?:因为|，|,|。|$)'
```

### 5.2 L1 revert（`capture/revert_l1.py`）

Claude Code：

```python
def detect(session) -> list[Candidate]:
    out = []
    for e in store.tool_edits.since_last_user_turn(session):
        cur = sha256(read(e.path)) if exists(e.path) else None
        if cur == e.sha_after: continue                    # 用户没动
        # 方向判断：Agent 改动 vs 当前工作树相对 HEAD 的 diff
        agent_hunks = store.tool_edits.hunks(e)            # post_tool 时保存的 diff 摘要
        now_diff = run(f"git diff -U0 -- {e.path}")
        if hunks_reverted(agent_hunks, now_diff):          # Agent 加的行被删 / 删的行回来了
            out.append(Candidate(level="L1", layer_guess="preference", kind="revert_and_redo",
                                 turn_idx=e.turn_idx, text=summarize(agent_hunks, now_diff),
                                 files=[e.path], confidence=0.7 if now_diff else 0.5))
    return out
```

Codex：在 `reconcile.run` 内，取增量 transcript 中 assistant 声明修改的文件（工具调用 `apply_patch` 的路径），与 `git diff --name-only` 比对；出现在前者不在后者（即改动被撤销）→ `revert_and_redo`，置信 0.5。

### 5.3 缓冲

`buffer` 表按 `(host, session_id)` 追加；`consumed=0` 的行是下次对账的输入；对账成功后置 1。`session_start` 的 `flush_orphans` 处理上次崩溃遗留（`ended=0 ∧ last_event_at < now−30min`）。

## 6. 对账实现（`reconcile/`）

### 6.1 `run(session, reason)`

```python
async def run(session, reason):
    async with locks[session.key]:                                  # 同会话串行
        turns = hosts[session.host].read_incremental(session)       # §6.2，更新 cursor_offset
        if not turns and not store.buffer.unconsumed(session): return
        cands = store.buffer.unconsumed(session) + host_specific_l1(session, turns)
        summary = compress(turns, budget=6000)                      # §6.3
        anchors = await select_anchors(session, summary)            # §6.4
        deltas = await judge(anchors, cands, summary, session)      # §6.5
        deltas = second_check(deltas, anchors)                      # §6.6
        ops, pendings = plan(deltas, anchors, session)              # §6.7–6.8
        await writer.apply(ops)                                     # §6.9
        store.pending.add_all(pendings); store.buffer.consume(cands)
        await tasks.update_from_session(session, turns, deltas)     # §7
        store.traces.add(reconcile_trace(...))
```

### 6.2 transcript 增量读取（`hosts/*.py`）

两宿主都是 JSONL。从 `cursor_offset` 起按行读；只接受完整行（最后一行无 `\n` 则不前进游标）。归一化：

| 宿主 | user | assistant | tool |
|---|---|---|---|
| Claude Code | `type=user ∧ message.role=user` 的 text 块 | `type=assistant` 的 text 块；`tool_use` 块 → ToolCall | `tool_result` 块 → 挂到对应 ToolCall 的 `output_digest`（前 500 字 + sha） |
| Codex | rollout 中 `role=user` 的 message | `role=assistant` message；`function_call`（如 `shell`、`apply_patch`）→ ToolCall | `function_call_output` → output_digest |

格式解析失败的行跳过并计数；连续 50 行失败 → 本次对账降级为"只用 buffer 候选，不读 transcript"（§9）。

### 6.3 确定性压缩 `compress(turns, budget)`

优先级从高到低保留：① 全部 user turn 原文（单条截到 600 字）② assistant turn 中"我将/已修改 X"类声明句与含文件路径的句子 ③ 失败的 tool 输出前 300 字 ④ 其余 assistant 文本每条前 200 字。超预算从 ④ 开始丢。输出带 `turn_idx` 标记，供 grounding 定位。

### 6.4 锚点选择 `select_anchors`

```python
async def select_anchors(session, summary) -> Anchors:
    seen = store.recalled.uris(session)                              # 本会话注入过的
    hits = await ov.find(query=summary.head(1000), target_uri=[dev_root], limit=60,
                         score_threshold=0.3, read_content=False)
    pool = merge(seen, hits)                                         # 以 uri 去重，保留最高分
    for r in pool: r.rank = r.scope.specificity * (r.score or 0.5)
    full = top_with_type_floor(pool, n=cfg.anchor_full_max, per_type_min=2)
    brief = [r for r in pool if r not in full][:cfg.anchor_brief_max]
    full = await ov.read_many(full)                                  # 取 MEMORY_FIELDS
    return Anchors(full=full, brief=brief)
```

### 6.5 判定 `judge`（一次 LLM 调用）

**system prompt 要点（固定文本，版本号进 trace）：**

1. 你是记忆对账器。输入：已有记忆（锚点，含字段与 URI）、本会话候选事件、会话摘要。输出：相对锚点的增量列表。
2. 五种 relation 的定义与判定顺序：先找同 key/同义锚点；有且一致 → `confirm`；有且补充细节 → `refine`；有且被明确推翻（用户用了"以后/always/改成/不再"或明确陈述新决策）→ `supersede`；有且矛盾但无强信号 → `conflict`；没有 → `new`。
3. 层判定规则（04 v0.2 §2.7）逐字给出；同句含两层拆两条。
4. 只输出 `generalizable` 的内容；一次性指令（"这次先不加测试"）丢弃，task 层例外。
5. 每条必须给 `grounding.turn_range` 与 ≤160 字 `quote`，`quote` 必须是摘要中原文。
6. 保守：不确定就不输出。宁缺毋滥。

**user 内容：** `## Anchors (full)` 每条 `URI / type / fields(JSON)`；`## Anchors (brief)` 每条 `URI / type / key / 一行摘要`；`## Candidates` 每条 `turn_idx / kind / text / files`；`## Session summary` 压缩文本；`## Context` repo_key、branch、cwd、日期。

**输出 schema：** `list[Delta]` 的 JSON schema（pydantic 生成），走 provider 的 structured output（OpenAI-compatible `response_format=json_schema`；Anthropic 用 tool_use 强制单工具）。

**失败处理：** 解析/校验失败 → 重试一次（temperature 0）；再失败 → 返回空列表并记 `judge_failed`；此时 §6.7 只把 L0/L1 候选写成 `dev_correction`（不需要模型字段），不创建任何 upsert 记忆。

### 6.7 路由与写入策略 `route`

### 6.8 演化 `evolve(existing: MemoryRecord | None, d: Delta) -> (list[WriteOp], list[Pending])`

```python
def evolve(ex, d, now):
    if ex is None:                                   # relation 必为 new
        f = base_fields(d) | {"confidence": 0.5 + 0.1*1, "evidence_count": 1, "contra_count": 0,
                              "valid_from": now.date(), "status": "active", "last_confirmed": now.date(),
                              "evidence": json([d.grounding])}
        return [WriteOp(uri_for(d), "create", d.type, f, render(d.type, f), None)], []
    f = dict(ex.fields)
    match d.relation:
        case "confirm":
            f["evidence_count"] += 1; f["last_confirmed"] = now.date()
            f["evidence"] = push_evidence(f["evidence"], d.grounding, cap=10)
        case "refine":
            for k, v in d.fields.items(): f[k] = merge_op(schema[d.type][k], f.get(k), v)   # §6.9 语义
            f["evidence_count"] += 1; f["last_confirmed"] = now.date()
            f["evidence"] = push_evidence(...)
        case "supersede" if d.strong_signal:
            f["status"], f["superseded_by"] = "superseded", uri_for(d, suffix=now.strftime("%Y%m%d"))
            f["contra_count"] += 1
            new_f = base_fields(d) | {...active, evidence=[d.grounding] + last_two_reversals(ex)}
            return [WriteOp(ex.uri, "update", ..., f, ..., ex.version),
                    WriteOp(f["superseded_by"], "create", ..., new_f, ..., None)], []
        case "supersede" | "conflict":                 # 无强信号 → 待确认
            f["status"] = "pending_confirm"; f["contra_count"] += 1
            return [WriteOp(ex.uri, "update", ..., f, ..., ex.version)], [Pending(ex, d)]
    f["confidence"] = confidence(f, now)
    if f["confidence"] < 0.3 and months_since(f["last_confirmed"], now) >= 3: f["status"] = "retired"
    return [WriteOp(ex.uri, "update", d.type, f, render(d.type, f), ex.version)], []

def confidence(f, now):
    decay = 0.05 * months_since(f["last_confirmed"], now)
    return clamp(0.5 + 0.1*f["evidence_count"] - 0.2*f["contra_count"] - decay, 0.1, 1.0)
```

同一 key 的新记录 URI 用日期后缀避免冲突（`ts_no_any-20260904.md`）；`topic` 字段不变，召回时按 `status=active` 过滤。

### 6.9 merge_op 与写入（`memory/merge_op.py`、`memory/writer.py`）

- `immutable`：新值≠旧值 → 拒绝本条 refine，记 trace（模型试图改 key）。
- `replace`：直接覆盖。
- `sum`：数值相加。
- `patch`：目标是"新值成为字段内容"，客户端计算 `difflib` 最小 SEARCH/REPLACE 块只为日志与上游兼容，实际写入的是新值全文。

```python
async def apply(ops):
    for batch in chunk(ops, 20):
        await asyncio.gather(*(apply_one(op) for op in batch))

async def apply_one(op, attempt=0):
    if op.mode == "update":
        cur = await ov.read(op.uri)                                   # 取当前 version
        if cur.version != op.expected_version:
            if attempt >= 3: raise Conflict(op.uri)
            merged = rebase(op, cur)                                  # sum 字段按差值重放；replace/patch 以本次为准；immutable 校验
            return await apply_one(merged.with_version(cur.version), attempt+1)
    content = memfile.serialize(op.body_after, op.fields_after | {"version": (op.expected_version or 0) + 1})
    await ov.write(op.uri, content, mode="replace", wait=False, processing_mode=cfg.ov.processing_mode)
```

`processing_mode` 默认用服务端缺省；VERIFY-1 若发现不建索引，切到强制语义处理的模式（Phase 0 确定枚举值）。

## 7. 任务生命周期实现（`tasks/lifecycle.py`）

```python
def resume_candidate(repo_key, branch) -> Resume | None:
    cands = store.tasks_index.active(repo_key, since=now - 14d)
    if not cands: return None
    if branch and (m := [t for t in cands if t.branch == branch]): return Resume(m[0], auto=True)
    return Resume(most_recent(cands), auto=False)          # session_start 注入一行提示，prompt 时二次判定

async def update_from_session(session, turns, deltas):
    task = store.tasks_index.get(session.task_id) or maybe_create(session, turns, deltas)
    if not task: return
    d = next((x for x in deltas if x.type == "dev_task"), None)
    fields = existing_fields(task) 
    if d: fields = fields | d.fields                          # 模型给的 done/open/next
    fields["touched_paths"] = union(fields["touched_paths"], edited_paths(turns))
    fields["last_active"] = now; fields["sessions"] = append((session.host, session.session_id))
    if merged_into_default(task.branch): fields["task_status"] = "done"; await distill_to_l3(task)
    await writer.apply([WriteOp(task.uri, "update", "dev_task", fields, render(...), task.version)])
    store.tasks_index.upsert(task)

def sweep():                                                  # 每日一次（daemon 内定时）
    for t in store.tasks_index.active_all():
        if now - t.last_active > 30d: mark(t, "abandoned")
```

`distill_to_l3`：把任务的 `done/open` 与其 `sessions` 对应的历史 trace 中已写入的 L3 记忆做一次对照，只对**尚未沉淀**的条目再跑一次小范围 `judge`（锚点限定该 repo 的 L3），避免重复。

## 8. 外部接口契约

### 8.1 OpenViking（`memory/ov_client.py`，httpx.AsyncClient，连接池 10，超时 read 5s / write 15s）

| 用途 | 请求 | 关键字段 |
|---|---|---|
| 列表/语义召回 | `POST /api/v1/search/find` | `query`（空串 = 列表）、`target_uri: str \| list[str]`、`limit`、`score_threshold`、`read_content`、`context_type`（可不传，靠 target_uri 限定） |
| 读一条 | `GET /api/v1/content/read?uri=…` | 返回正文；解析 `MEMORY_FIELDS` 得 `version` |
| 写一条 | `POST /api/v1/content/write` | `{uri, content, mode:"replace", wait:false, processing_mode, tags?}` |
| 批量写 | `POST /api/v1/content/batch-write` | 同上数组（Phase 0 确认 body 形状） |
| 删除 | `DELETE /api/v1/content?uri=…` 或对应路由（Phase 0 确认） | `forget` 用 |
| 使用反馈 | `POST /api/v1/sessions/{id}/used` | `{contexts: [uri]}` |
| 健康 | `GET /api/v1/system/health`（或 `/status`，Phase 0 确认） | `doctor` 用 |

请求头：`Authorization: Bearer <api_key>`；可选 `X-OpenViking-Account`、`X-OpenViking-User`。`viking://~/` 别名由服务端展开为当前用户，我们统一用 `~` 形式，不拼 user_id。

重试：幂等请求（find/read）指数退避 3 次（100/300/900ms）；write 不自动重试（由 §6.9 的版本冲突逻辑处理）；连接失败进入"OV 离线"状态 60s，期间召回直接返回空、对账推迟。

### 8.2 LLM（`llm/provider.py`）

统一接口 `await judge_structured(system: str, user: str, schema: type[BaseModel], max_tokens=4000) -> BaseModel`。
- OpenAI-compatible：`/chat/completions` + `response_format={"type":"json_schema", ...}`；不支持时退化为 prompt 内嵌 schema + 严格 JSON 解析。
- Anthropic：`/v1/messages` + 单 tool 定义 + `tool_choice={"type":"tool","name":...}`。
- 从 `ov.conf` 推导：读 `[vlm]` 段的 `provider/base_url/api_key/model`（字段名以 Phase 0 读到的实际配置为准）。

### 8.3 embedding（`llm/embed.py`）

`await embed(texts: list[str]) -> list[list[float]]`，OpenAI-compatible `/embeddings`；LRU 缓存 2000 条（key=sha1(text)）。`provider="none"` 时 `similarity()` 用 `rapidfuzz.fuzz.token_set_ratio/100`，阈值单独配置（`dedup_similarity_lexical=0.9`）。trace 记录 `sim_backend`。

## 9. 错误与降级矩阵

| 故障 | 检测 | 行为 | 用户可见 |
|---|---|---|---|
| daemon 未启动 | shim curl rc=7 | shim 拉起 daemon，本次输出 `{}` | 本轮无注入 |
| daemon 超时 | shim `-m 0.8` | 输出 `{}` | 本轮无注入 |
| OV 不可达 | httpx ConnectError | 60s 内不再尝试；候选留 buffer；对账推迟到下次事件 | `sagactl status` 显示离线 |
| OV 写版本冲突 3 次 | §6.9 | 该 op 放弃，记 trace；其余 op 继续 | `explain` 可见 |
| judge 解析失败 ×2 | §6.5 | 只写 `dev_correction`，不建 upsert 记忆 | 下次会话不会出现新约定 |
| embedding 不可用 | 请求失败 | 本次用词法相似度，trace 标注 | 无 |
| transcript 解析连续失败 | §6.2 | 只用 buffer 候选 | 无 |
| transcript 文件不存在 | stat 失败 | 同上 | 无 |
| 非 git 目录 | scope.resolve | `repo_key_kind=path`，无 revert 检测 | 无 |
| 记忆正文含可疑指令 | render 时检测 `<memory`/`</memory` 字样 | 转义并标 `suspicious=1` | trace |
| daemon 崩溃 | launchd/systemd 自动重启 | `session_start` 的 `flush_orphans` 补对账 | 无 |

原则：**任何路径失败都不能阻塞宿主的正常工作**。

## 11. 性能预算

| 路径 | 预算 | 主要开销 |
|---|---|---|
| shim 往返（daemon 空转） | p95 < 100ms | curl 启动 + FastAPI 路由 |
| `session_start` | p95 < 600ms | 3 次并发 find（各 ~150ms）+ 渲染 |
| `prompt` | p95 < 400ms | 2 次并发 find + L0 正则 + L1 哈希（≤10 个文件） |
| `pre_tool` | p95 < 50ms | 内存索引查询，无网络 |
| `stop / session_end` | < 20ms 返回 | 只投递任务 |
| 一次对账（后台） | 中位 < 15s | 1 次 LLM（输入 ≤12k token）+ ≤60 次 read + ≤20 次 write |
| daemon 常驻内存 | < 150MB | httpx 池 + embedding LRU |

## 12. M2–M4 实现要点

**M2 Compliance**
- `compliance/compiler.py`：`dev_convention` with `check_hint≠none ∧ confidence≥0.6 ∧ status=active` → 内存规则表，`session_start` 时构建，写回后失效重建。
- `exec_path`：`fnmatch` 目标路径与 `check_spec.paths/forbid_paths`。`exec_pattern`：预编译正则跑在 `tool.input.new_string`/`content` 上。二者在 `pre_tool` 同步执行，预算 150ms，返回 `permissionDecision: "deny"` + reason（含规则 URI）或 `allow` + warn 文本。
- `exec_command`：`stop` 后台对本轮 `tool_edits` 的文件跑 `check_spec.command`，失败结果存 `sessions.pending_violations`，下一次 `prompt` 注入。
- 违规 → `dev_correction(kind=compliance_violation)`，`evidence_count` 不变；连续 3 次用户对同规则 block 后说"这次就这样"（L0 规则 `override_once`）→ 该规则 `check_spec.mode=warn` 并入 pending。
- Codex：无 `pre_tool`，`exec_path/pattern` 在对账时对 transcript 声明的修改做事后检查，结果走下一轮注入。

**M3 学习**
- `weights` 表 (user, layer, type, scope_level) → w。信号：`record_used`（+1）、产出引用（+1）、注入后同 key 被纠正（−2）、注入但违反（−1）。`w ← clamp(w + 0.05·reward, 0, 2)`，每周 `w ← 1 + 0.9·(w−1)`。
- 排序分接入 `render.rank_key`；trace 里每条注入记 `(confidence, w, specificity, score)`。
- L6：`find target_uri=viking://~/memories/experiences/` 取与当前 repo 相关的 experiences 作 `prompt` 召回的第四类候选（预算内最低优先）。

**M4 团队与加固**
- `team/publisher.py`：`sagactl team publish <uri>` → 读个人记忆 → 改 `origin=team`、去 `evidence` 中的 session 细节 → 写 `viking://resources/sagacontext/team/{repo_key}/<type>/<key>.md`；ACL 通过上游 ACL 接口授予 `group:<team_id>` write。
- 召回：`session_start` 多一次 `find target_uri=viking://resources/sagacontext/team/{repo_key}/`，按路径重打 `layer/type`，与个人记忆合并；同 key 冲突时个人优先并标注。
- 脱敏规则集（API key / token / 私钥头 / `.env` 行 / 邮箱）+ 单测；`forget` 两端一致性；daemon 可选 token；泄漏测试进 CI。
