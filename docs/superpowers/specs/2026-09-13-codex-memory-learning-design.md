# Codex 记忆机制学习可视化设计

## 目标

读取用户本地 Codex 源码与会话数据，以只读、可追溯的方式展示上下文压缩、短期记忆滚动和长期记忆写入过程，帮助用户理解当前本地版本的实际行为。

## 范围

首期支持 Codex：源码参考目录可配置，默认识别本地 checkout；会话读取器从 `~/.codex/sessions` 读取。版本解析优先使用源码 commit 与可执行文件版本，无法确认时标记未知。页面默认展示摘要，点击事件后查看经过脱敏的原文。

## 页面与事件

页面包含总览、会话回放、压缩检查器、长期记忆检查器和源码对照。统一事件包含时间、会话、类型、摘要、来源文件/行号、证据等级和可选原文。事件类型包括消息追加、上下文快照、压缩开始/结束、摘要生成、记忆候选、记忆写入/跳过、召回和取代。

## 边界与验证

所有读取 API 只读本地文件与 Ledger，不调用写入、Judge 或后端检索。解析失败保留为未解析事件并说明原因。Codex 原生行为、SagaContext 记忆写入和页面推断分别标注。使用脱敏 fixture 覆盖版本差异、压缩、截断和坏文件，并以一份真实本地会话人工核对时间顺序、token、源码定位和记忆链路。

## 2026-09-13 资产中心交互定稿

本轮确认采用“记忆资产中心”作为主入口。资产卡片以内容为主，同时补充生命周期信息，让用户先回答“这条记忆是什么”，再理解“它如何形成、现在是否仍在使用”。

### 页面职责

- **总览**：展示产品状态、资产数量、最近形成/召回活动，并提供一条可播放的记忆旅程。
- **记忆资产**：以卡片网格展示标题、摘要、来源会话数、引用次数、最近状态、生命周期状态和证据等级。
- **资产详情抽屉**：点击卡片后展示摘要与状态，并按“形成 → 写入 → 使用 → 更新/取代”四段轨道呈现时间、来源文件/行号、证据等级；可跳转到原始会话或源码对照。
- **形成过程**：跟随当前资产展示候选、判断、写入/跳过和取代过程。
- **短期上下文**：保留上下文增长与压缩播放，并提示压缩摘要和长期资产的关联。
- **源码对照**：保留源码事实定位与漂移状态；Claude Code 无源码对照时显示能力边界。

### 交互与数据边界

资产详情优先使用现有只读 API 返回的数据，不引入新的写入路径。无法确认的写入时机、召回规则或跨产品关系显示为“未知/推断”，不补造事实。资产卡片与详情抽屉共享当前选中资产，切换产品或刷新页面时清空选择，避免把 Codex 资产误用于 Claude Code。

### 验收标准

1. 用户从总览进入资产页后，三秒内能看懂资产内容、来源规模和当前生命周期状态。
2. 点击任一资产可在同一页面打开详情抽屉，并看到至少一条可定位的本地数据证据；缺失证据时明确显示缺失原因。
3. 形成过程、短期上下文和源码对照均能从资产详情回到对应页面，且产品切换后数据不串线。
4. 所有源码事实、本地数据事实和系统推断在结论旁显式标注，现有脱敏规则继续生效。
