# Public README 设计

## 目标

把根目录 README 从“项目背景、内部验收记录和长期设计混合页”收敛为面向潜在用户的公开首页。读者无需了解内部探针、实验台账或实现分期，也能判断 SagaContext 解决什么问题、是否适合自己、如何开始使用。

## 公开内容

README 保留以下信息：

- 一句话定位和面向 Coding Agent 用户的价值主张。
- 用户痛点、典型使用场景和可理解的工作方式。
- 当前可用能力：本地记忆、项目/任务范围、证据与生命周期、只读控制台、部署脚本。
- 快速开始：环境要求、安装、启动、打开控制台和停止服务。
- 默认安全行为：loopback、rollout off、不会自动启用 hooks、不会自动写入外部后端。
- 当前版本边界、隐私说明、文档入口、贡献方式和许可证。

## 移出或改写的内容

- 删除内部验收编号、探针路径、具体实验台账、内部绝对路径和宿主调试细节。
- 不在首页公开 endpoint、凭据文件位置、内部服务配置或本机运行记录。
- 将“产品目标”改成“当前能力”与“规划方向”两类，避免把设计建议写成已完成事实。
- 保留必要的真实性说明，但使用用户能理解的表达，不用内部阶段编号作为主叙事。

## 页面结构

1. 项目名称、定位和简短状态说明。
2. 为什么需要它：跨会话、跨项目和纠正记忆的具体问题。
3. 核心能力：分层记忆、范围隔离、证据和生命周期、可观察性。
4. 使用示例：从安装到启动控制台的最短路径，以及一个跨会话场景。
5. 安全与隐私：默认关闭、显式启用、敏感信息不写入仓库。
6. 当前边界：本地单用户、需要显式配置、部分自动化仍需单独验证。
7. 文档、贡献和许可证链接。

## 验证标准

- 新读者只读 README 就能回答“它是什么、有什么用、怎么开始”。
- README 中的命令与当前脚本和文档一致。
- 不出现内部 endpoint、secret、绝对用户路径、探针编号或未验证指标。
- 所有能力描述都能在当前代码或公开文档中找到依据。
