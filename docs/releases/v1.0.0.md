# SagaContext 1.0.0

V1 定位为**需要审核的本地 Codex 记忆系统**。本版冻结已经有运行证据的 Ledger、Judge、调度、审核、召回与回滚能力，作为 main 的首个实现基线。安装默认 off；版本发布不授权新 workspace，不续期现有 rollout。

## 交付范围

- SQLite Ledger 权威数据、持久化 event/candidate/batch/proposal、lease/CAS/幂等回执。
- 真实 Judge 提案、人工或明确授权代理逐条审核、同事务 commit 门禁；不开放无人审核 active。
- 真实 Codex hooks → daemon → 后台 scheduler → Judge → 审核 → OpenViking projection → 下一会话召回与独立消费回执。
- owner/workspace/scope/revision/generation 过滤，STOP、deadline、配额 reservation 和在途补偿。
- rollback 精确归属与 locator 删除、cleanup_required、重启恢复、失败与成功补偿回执。
- CLI 队列/审核/标注/报告；独立每分钟 launchd 观察巡检、限时关闭和清理。

首轮日常观察只允许当前项目 scope 的 new proposal 写入。已有记忆的 refine/supersede 等语义处理在底层与受控测试中存在，但不作为本版日常观察可逆写入承诺。最多 10 session、20 candidate、24 小时，不能自动续期。

## 已知限制

- 日常候选准确率、错误召回率和长期 provider 延迟尚未达成质量验收；受控成功不能替代真实日常样本。一次实际宿主调用仍耗时约 80 秒。
- 已通过真实宿主链路的是固定版本 Codex；其他 Codex 版本、Claude Code 全链路及跨宿主共享需独立准入。
- 不提供无人审核写入、历史 transcript 导入、全局/跨项目自动扩围、团队协作或遵守约束的完整产品承诺。
- 启动/停止、hooks 与观察脚本以源码 checkout 为运行布局；观察巡检依赖 macOS launchd。本版 Python wheel 提供运行模块，不是完整跨平台一键安装器。
- 电脑休眠或登出时无法执行清理；恢复后巡检继续，已持久化 hard deadline 不延长。清理失败保持 STOP 和 cleanup_required，不能宣称资源已删除。
- 消费标签和宿主实际消费回执分离；缺少证据为 unknown/null。
- 工作区可视化控制台是后续独立分支工作，不包含在本次 main 合并内。

## 本地运行与升级

从源码使用 `uv sync --locked --group dev`，再执行 `uv run --locked pytest -q`。真实集成需另配置已授权 Judge、普通用户 OpenViking namespace 和固定宿主 hooks，参考 [操作说明](../probes/2026-09-11-daily-observation.md)。不得把仓库示例或历史 artifact 中的状态当作启用授权。

已有部署先完成当前 rollout 的停止/清理，备份本机 Ledger 与配置，再按显式操作重启 daemon；不要因合并 main 自动迁移活跃服务。本次版本变更仅改发布 metadata/文档，不改运行协议、不重启本机正在观察的 daemon。
