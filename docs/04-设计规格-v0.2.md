## 0. 一页总览

SagaContext 是叠在 OpenViking 之上的**分层开发者个性化记忆**：会话开始按层召回与当前 repo / 任务相关的已有记忆，会话结束时以这些记忆为锚做增量对账（确认 / 补全 / 取代 / 新增 / 冲突），而不是从零抽取。

```
Codex / Claude Code ──(上游插件 hooks)──► OpenViking sidecar
        │                                       ▲   ▲
        │ transcript / tool 轨迹                 │   │ 自定义 memory type (yaml)
        ▼                                       │   │ viking://user/{uid}/memories/dev/**
[sagactl daemon]                                │   │
  ├─ Recall Policy ── 按层/scope 召回 → 锚点集 A ─┘   │   (M1 基线，M3 学习)
  ├─ Candidate Buffer ── 会话中只缓冲，不写         │
  ├─ Reconciler ── 锚定抽取 + 分层路由 + 演化状态机 ──┘   (M1)
  ├─ Compliance Compiler ── convention → 可检查规则     (M2)
  ├─ Team Publisher ── 个人记忆 → viking://resources 共享   (M4)
  └─ Eval Runner ── DevPref-Bench + ProjMem-Bench
```

四个不可让步的边界（与 v0.1 相同）：
1. **不修改 OpenViking 服务端代码**；只用 `memory.custom_templates_dir`、HTTP/MCP API、上游插件的 hook 事件。
2. **一切记忆有 grounding**：每条都能回到产生它的原始 turn。
3. **冲突不静默覆盖**：进待确认队列，用户不确认则两版并存并标注。
4. **数字全部 `[TARGET]`**，直到 Eval Runner 跑出来。

## 1. 术语

| 术语 | 含义 |
|---|---|
| **层 (layer)** | L1 用户 / L2 偏好 / L3 项目 / L4 任务 / L5 团队 / L6 Agent 经验（05 §2） |
| **纠正 (correction)** | 用户对 Agent 产出的否定/修改，含显式与隐式（撤销 Agent 改动后手动改回） |
| **约定 (convention)** | 可判定的规则："在 scope S 内，条件 C 时，应/不应 X" |
| **口味 (taste)** | 不可硬判定的倾向：解释详略、评审严格度、风险偏好、工具习惯 |
| **决策 (decision)** | 项目内的技术选择及理由，ADR 口径 |
| **模块地图 (project_map)** | 组件 → 职责 → 路径 → 依赖 |
| **坑 (gotcha)** | 环境或失败模式：症状 → 原因 → 修法 → 触发路径 |
| **任务 (task)** | 跨会话的一段工作：目标 / 已完成 / 未决 / 下一步 |
| **scope** | `global` / `repo:<repo_key>` / `glob:<repo_key>:<pattern>` |
| **锚点集 (anchor set)** | 会话中召回的、与本会话相关的已有记忆；对账时作为增量判定的参照 |
| **grounding** | `(source_agent, session_id, turn_range, tool_call_ids?, git_root, git_rev, files, quote)` |
| **演化状态** | `active` / `superseded` / `pending_confirm` / `retired` |

## 2. 记忆 Schema

### 2.1 落地方式

**类型注册。** OpenViking 通过 `memory.custom_templates_dir` 加载自定义类型（`memory_type_registry.py` `_load_schemas`，`replace=True` 可覆盖同名内置类型）。SagaContext 提供模板目录 `templates/memory/*.yaml`，安装时写入 `ov.conf`：

```toml
[memory]
custom_templates_dir = "~/.sagacontext/templates/memory"
```

yaml 顶层键（源码核对内置模板）：`memory_type / description / directory / filename_template / enabled / operation_mode(upsert|add_only) / stage(user|agent) / agent_only / embedding_template / overview_template / fields[]`；每个 field 有 `name / type / description / merge_op`。

**文件格式。** 记忆文件 = Markdown 正文 + 末尾 `<!-- MEMORY_FIELDS\n{json}\n-->` 块（`memory_file_utils.py`，含自增 `version`）。

**写入路径（v0.2 决定）。** Reconciler **直接**用 `POST /api/v1/content/write` 按上述格式写文件到类型的 `directory` 下，不经上游 Phase 2 抽取。理由：上游抽取 prompt 要求"omit supporting evidence"，且不能拿锚点集做增量判定；我们自己的判定模型已经产出结构化字段。注册类型 yaml 的作用是让上游把这些目录当记忆处理（索引、overview、召回分类、`record_used`），并在用户误用 `remember` 等入口时有正确 schema。**[VERIFY-1]** 直接写入的文件是否与抽取写入的文件在检索/配额上同等对待（预期是：按目录归类，是）。

### 2.2 上游能力与约束

| 能力 | 事实 | 对设计的影响 |
|---|---|---|
| 字段类型 | `FieldType` 仅 `string / int64 / float32 / bool`（`merge_op/base.py`） | 列表与对象序列化为 string（JSON 或 Markdown 列表） |
| 字段合并 | `patch`（SEARCH/REPLACE）/ `replace` / `sum` / `immutable` | 由上游 `remember` 路径触发时生效；Reconciler 直接写时自己实现同语义 |
| 类型级模式 | `operation_mode: upsert \| add_only`；`stage`；`agent_only` | 事件型（correction）用 `add_only`；状态型用 `upsert` |
| 目录与文件名 | `directory` 用 `{{ user_space }}`；`filename_template` 可含子路径 | scope 编进路径 |
| supersedes | 仅 experiences 类型有（`agent_experience_context_provider`） | 演化逻辑在 SagaContext 侧 |
| 记忆文件格式 | Markdown + `MEMORY_FIELDS` JSON 尾块 | 直接写入可行 |
| peer 命名空间 | `viking://user/{uid}/peers/{peer_id}/...`，"当前用户边界内的交互对象"（`11-multi-tenant.md`）；其他用户不可见 | **不能承载团队层**，见 §2.4 L5 |
| 共享资源 + ACL | `viking://resources/...` 是账户内共享 scope，支持 `user:` / `group:` 级 `read/write/manage` ACL（`15-acl.md`） | 团队层载体 |
| 代码仓解析 | `CodeRepositoryParser` 可把 repo 加为 resource 并提取代码骨架（`06-extraction.md`） | 模块地图冷启动的可选来源，非必需 |

### 2.3 公共字段（所有 upsert 类型共有）

| 字段 | 类型 | merge_op | 说明 |
|---|---|---|---|
| `scope_key` | string | immutable | `global` / `repo-<8hex>` / `glob-<8hex>-<slug>`；进路径 |
| `scope_pattern` | string | replace | glob 的原始 pattern；非 glob 为空 |
| `layer` | string | immutable | `user / preference / project / task` |
| `confidence` | float32 | replace | 0–1，Reconciler 维护（§3.5） |
| `evidence_count` | int64 | sum | 支持该记忆的观测次数 |
| `contra_count` | int64 | sum | 矛盾观测次数 |
| `valid_from` | string | replace | ISO 日期 |
| `superseded_by` | string | replace | 取代者的 URI；非空即 `superseded` |
| `status` | string | replace | `active / superseded / pending_confirm / retired` |
| `last_confirmed` | string | replace | 最近确认或遵守观测日期 |
| `origin` | string | replace | `self / team / coldstart`（L5 与冷启动用） |
| `evidence` | string | patch | JSON 数组，每项一条 grounding（§2.5），最多 10 条，最旧淘汰 |

### 2.4 类型定义

八个类型。L1–L4 全部 `stage: user`，根目录 `viking://user/{{ user_space }}/memories/dev/`。

#### L1 `dev_profile`（upsert，单文件）

`directory: .../memories/dev`，`filename_template: profile.md`。**不覆盖**内置 `profile`（决议见 §10），注入时优先本类型。

| 字段 | merge_op | 说明 |
|---|---|---|
| `stack` | patch | 语言/框架/工具，Markdown 列表，每项带 "as of YYYY-MM" |
| `experience_level` | replace | `junior / mid / senior / staff`，用户自述或长期观测 |
| `roles` | patch | 如 backend、infra、reviewer |
| `working_hours_tz` | replace | 时区 |
| `explanation_language` | replace | 解释用语言 |
| 公共字段 | | scope 恒为 `global` |

#### L1 `dev_taste`（upsert）

`filename_template: taste/{{ scope_key }}/{{ dimension }}.md`

| 字段 | merge_op | 说明 |
|---|---|---|
| `dimension` | immutable | 枚举：`explanation_depth / review_strictness / risk_tolerance / tool_habit / communication_style / test_appetite` |
| `content` | patch | Markdown bullets，每条一个可复用倾向 |
| 公共字段 | | |

#### L2 `dev_convention`（upsert）

`filename_template: convention/{{ scope_key }}/{{ topic }}.md`

| 字段 | merge_op | 说明 |
|---|---|---|
| `topic` | immutable | 唯一键，snake_case ≤5 词，如 `ts_no_any`、`tests_location` |
| `rule` | patch | **可判定**的一句话规则，祈使句，含条件 |
| `rationale` | patch | 用户给的理由（若有） |
| `check_hint` | replace | `path / pattern / command / none`，供 M2 编译 |
| `check_spec` | replace | 编译参数（JSON string）：path 约束 glob、pattern 正则、command 命令行 |
| 公共字段 | | |

#### L2 `dev_correction`（add_only，事件型）

`filename_template: correction/{{ scope_key }}/{{ occurred_date }}/{{ correction_id }}.md`

| 字段 | merge_op | 说明 |
|---|---|---|
| `correction_id` | immutable | `<session_id>-<turn>` |
| `kind` | immutable | `explicit_negation / explicit_instruction / revert_and_redo / edit_after_agent / compliance_violation` |
| `agent_did` | immutable | Agent 原产出摘要 ≤200 字 |
| `user_wanted` | immutable | 用户要的 ≤200 字 |
| `derived_uri` | replace | 归并到的 convention/taste/decision URI；空 = 未归并 |
| `grounding` | immutable | JSON（§2.5） |
| `occurred_at` / `occurred_date` | immutable | ISO 时刻 / `YYYY-MM-DD` |
| `scope_key` / `layer` | immutable | |

#### L3 `dev_decision`（upsert）

`filename_template: project/{{ scope_key }}/decision/{{ topic }}.md`

| 字段 | merge_op | 说明 |
|---|---|---|
| `topic` | immutable | 唯一键，snake_case ≤5 词，如 `orm_choice`、`auth_token_storage` |
| `decision` | patch | "选了 X"，一句 |
| `rationale` | patch | "因为 Z"，Markdown bullets |
| `alternatives` | patch | 被否掉的选项及原因，Markdown bullets |
| `affects` | patch | 受影响的路径/模块，Markdown 列表 |
| `decided_at` | replace | ISO 日期 |
| 公共字段 | | scope 恒为 `repo-*` 或 `glob-*`，不允许 `global` |

#### L3 `dev_project_map`（upsert）

`filename_template: project/{{ scope_key }}/map/{{ component }}.md`

| 字段 | merge_op | 说明 |
|---|---|---|
| `component` | immutable | 唯一键，如 `auth_service`、`cli_entry` |
| `responsibility` | patch | 一到三句 |
| `paths` | patch | 路径列表 |
| `entrypoints` | patch | 入口函数/文件 |
| `depends_on` | patch | 其他 component 名 |
| 公共字段 | | `origin=coldstart` 时 `confidence` 上限 0.3，见 §10 决议 3 |

#### L3 `dev_gotcha`（upsert）

`filename_template: project/{{ scope_key }}/gotcha/{{ topic }}.md`

| 字段 | merge_op | 说明 |
|---|---|---|
| `topic` | immutable | 唯一键，如 `pytest_asyncio_hang`、`docker_m1_platform` |
| `symptom` | patch | 现象（含关键报错原文 ≤160 字，已脱敏） |
| `cause` | patch | 原因 |
| `fix` | patch | 修法 |
| `trigger_paths` | patch | 触发路径 glob 列表；PreToolUse 提示用 |
| `trigger_commands` | patch | 触发命令片段列表 |
| 公共字段 | | |

#### L4 `dev_task`（upsert）

`filename_template: task/{{ scope_key }}/{{ task_id }}.md`

| 字段 | merge_op | 说明 |
|---|---|---|
| `task_id` | immutable | `<YYYYMMDD>-<slug>` |
| `goal` | replace | 一句话目标 |
| `branch` | replace | git 分支；非 git 为空 |
| `done` | patch | Markdown 列表 |
| `open` | patch | 未决项 / 阻塞 |
| `next` | replace | 下一步一句话 |
| `touched_paths` | patch | 涉及文件 |
| `task_status` | replace | `active / paused / done / abandoned`（与公共 `status` 区分） |
| `started_at` / `last_active` | replace | ISO |
| `sessions` | patch | 参与过的 `(source_agent, session_id)` 列表 |
| 公共字段 | | `confidence` 固定 1.0，不参与演化，只走生命周期（§3.7） |

#### L5 团队层（M4，不新建 memory type）

载体：`viking://resources/sagacontext/team/{{ repo_key }}/{convention,decision,gotcha}/*.md`，文件格式与对应个人类型相同，`origin=team`。ACL：`group:<team_id>` `write`，其他 `read`。由 `sagactl team publish <uri>` 从个人记忆复制发布，不自动写。召回时与个人记忆合并，冲突规则见 05 §2。**[VERIFY-2]** 共享 resource 目录下的 `MEMORY_FIELDS` 文件是否被检索层当普通 resource 处理（预期是），召回分类需在 SagaContext 侧按路径重打 layer。

#### L6 Agent 经验层（M3，不新建 memory type）

直接读上游 `experiences / cases / trajectories`（`agent_only`）。只作 P3 反馈学习的信号来源与 UserPromptSubmit 召回的候选，不进对账循环。

### 2.5 grounding 格式

```json
{
  "source_agent": "claude-code | codex",
  "session_id": "…",
  "turn_range": [12, 14],
  "tool_call_ids": ["toolu_…"],
  "git_root": "/abs/path",
  "repo_key": "8hex",
  "git_rev": "abc1234",
  "branch": "feat/x",
  "files": ["src/foo.ts"],
  "quote": "≤160 字原话（已脱敏）"
}
```

### 2.6 scope 与 repo_key

- `repo_key = sha1(first_commit_hash)[:8]`；无 git 或无提交时 fallback `sha1(realpath(cwd))[:8]` 并标 `repo_key_kind=path`（§10 决议 5）。
- 召回时给定 `cwd` 与当前编辑文件，生效 scope 集合 = `{global} ∪ {repo-<k>} ∪ {glob-<k>-* 中 pattern 命中者}`。优先级 glob > repo > global；同 topic 多 scope 并存取最具体者，其余标注"被 X 覆盖"。
- L3/L4 禁止 `global`。

### 2.7 层判定边界

Reconciler 的 L2 判定输出带 `layer`，规则：
- 能改写成"Agent 应/不应 X" → `preference`（convention 或 taste）。
- 只能改写成"项目是 X / 选了 X / 踩过 X" → `project`（decision / project_map / gotcha）。
- 描述"正在做什么、做到哪" → `task`。
- 描述用户自身（栈、角色、语言） → `user`。
- 同一句话同时含两层（"因为我们用 pnpm，所以别再写 npm install"）→ 拆两条：decision `package_manager` + convention `use_pnpm`，correction 的 `derived_uri` 指向 convention。

## 3. 对账循环

### 3.1 触发与输入

复用上游插件事件（Claude Code 9 hooks；Codex 4 hooks）。**会话中只读不写**（已拍板）。

| 事件 | 会话中（只读 / 缓冲） | 会话末（写回） |
|---|---|---|
| `SessionStart` | 召回锚点集 A（§4.1）；任务接续判定（§3.7） | — |
| `UserPromptSubmit` | L0 规则检测 → 候选进本地缓冲 C；增量召回 | — |
| `PostToolUse`（Claude Code） | 记录 Edit/Write 目标与 diff hash（revert 检测）；记录失败的 Bash/测试（gotcha 候选） | — |
| `Stop` | 扩充 A（本会话新召回的 URI） | 达阈值（复用上游 20000 token / 10 轮）或 C ≥ 20 条 → 对账写回 |
| `SessionEnd` | — | 无条件对账写回；更新 `dev_task` |
| `PreCompact` | — | 对账写回（抢救） |

Codex 无 `PostToolUse`：revert 检测改为 `Stop` 时对比 transcript 中 Agent 声明修改的文件与工作树 `git diff`；gotcha 候选只靠 transcript 里的报错文本。

本地缓冲 `~/.sagacontext/buffer/<source_agent>-<session_id>.jsonl`，进程异常退出后下次 `SessionStart` 扫描并补写（Codex 侧尤其需要，上游无磁盘队列）。

### 3.2 候选识别（分层，宁缺毋滥）

| 层级 | 方法 | 产出（含 `layer` 猜测） |
|---|---|---|
| L0 规则 | 否定/指令模式（中英）："不要/别/never/don't/stop using X"、"改成/use Y instead"、"以后都/always/from now on" → preference；决策模式："我们决定/改用/选 X 而不是 Y/because" → project.decision；坑模式：工具返回非零 + 之后 ≤3 轮内同文件/同命令成功 → project.gotcha；任务模式：会话首轮含"实现/修复/重构 …"且无活跃任务 → task | 候选，置信 0.6 |
| L1 结构 | Agent 上一轮 Edit 的文件在用户下一条 prompt 前被手动改回（diff hash vs 工作树） → `revert_and_redo` | 候选，置信 0.7 |
| L2 LLM 判定 | 对 L0/L1 候选 + 前后 2 轮上下文 + **锚点集中相关的 top-k 记忆**，输出 `{is_memory_worthy, layer, type, kind, agent_did, user_wanted, generalizable, proposed_key, proposed_scope, proposed_fields, anchor_uri, relation}`，`relation ∈ {confirm, refine, supersede, new, conflict}` | 过滤一次性指令；只保留 `generalizable=true`（task 层除外） |

### 3.3 锚定抽取

对账时交给判定模型的输入 = 本会话 transcript（或其摘要）+ 锚点集 A 的**完整内容**（上限见下）+ A 之外相关记忆的 **URI + 一行摘要**列表。输出必须是相对 A 的增量，不允许输出与 A 中某条语义相同却 `relation=new` 的记忆（Reconciler 二次校验：新记忆与 A 中同 layer 记忆 embedding 相似度 ≥0.85 → 强制改判 `refine` 并进人工抽检样本）。

**锚点上限（§10 决议 4）：** 完整内容 ≤20 条，按 `scope 具体度 × 与会话摘要相似度` 取 top，且每个出现过的 type 至少 2 条；URI+摘要列表 ≤60 条；超出的忽略。总输入预算 ≤12000 token，超出先压 transcript 再压列表。

### 3.4 写入策略（保守）

| 层 / 类型 | 创建条件 | 更新条件 |
|---|---|---|
| `dev_correction` | 全部写入（add_only，便宜可审计） | — |
| `dev_convention` / `dev_taste` | (a) 用户明确用了"以后都/always"类词，或 (b) 同 topic 同 scope 的 correction ≥2 次 | 每次 `relation=confirm/refine` |
| `dev_decision` | (a) 用户明确陈述决策及理由，或 (b) 同 topic ≥2 次一致观测（如两次会话都按 X 做且提及理由） | 同上；`alternatives` 只追加 |
| `dev_project_map` | (a) 用户陈述，或 (b) Agent 读/改了该 component 路径且会话中出现职责描述 ≥2 次，或 (c) 冷启动（§10 决议 3，`confidence≤0.3`） | `paths/entrypoints` 可由结构观测更新；`responsibility` 只由会话或用户陈述更新 |
| `dev_gotcha` | 一次失败 + 一次修复配对（同文件或同命令），且修法可复述 | `fix` refine；再次触发同 symptom → `evidence_count+1` |
| `dev_task` | 会话首轮任务陈述且无接续（§3.7） | 每次会话末 |
| `dev_profile` | 用户自述 | 用户自述或 ≥3 次观测一致 |

### 3.5 通用演化状态机（所有 upsert 类型）

```
                 新增量 (key K, scope S, relation R)
                          │
        ┌─────────────────┼──────────────────┐
        ▼                 ▼                  ▼
   无 active K       有 active K            有 active K
   (R=new)           R=confirm/refine       R=supersede/conflict
        │                 │                  │
  满足 §3.4 创建条件?  evidence_count+=1    contra_count+=1
        │            confidence↑            │
        ▼            last_confirmed         ▼
   创建 active K     (refine → patch)   强信号?（"以后都"/用户明确陈述新决策）
                                          ├─ 是 → 旧.status=superseded, superseded_by=新 URI
                                          │       新记录 active, valid_from=now
                                          └─ 否 → 旧.status=pending_confirm → 待确认队列
```

- `confidence = clamp(0.5 + 0.1·evidence_count − 0.2·contra_count − decay, 0.1, 1.0)`，`decay = 0.05 × 距 last_confirmed 的月数`；`< 0.3` 且 90 天无确认 → `retired`。
- 非单调：反转后再反转回来，不复活旧记录，创建新记录并让 `evidence` 引用两次反转。
- 遵守观测（M2）：通过检查且用户未纠正 → 刷新 `last_confirmed`，不加 `evidence_count`（避免自证）。
- `dev_task` 不走此状态机，只走 §3.7。

### 3.6 待确认队列

`~/.sagacontext/pending.jsonl`，每项含冲突双方 URI + grounding + 建议动作。
- `sagactl review`：逐条 keep old / take new / both with scopes / drop。
- `SessionStart` 注入一行提示（≤80 token）："有 N 条记忆冲突待确认，`sagactl review`"。
- 队列项 30 天未处理 → 双方都保留 `active` 并在注入时并列标注"存在未确认冲突"，不再提示。

### 3.7 任务生命周期（§10 决议 2）

**接续判定（`SessionStart`）：** 候选 = 同 `repo_key` 下 `task_status=active` 且 `last_active` ≤ 14 天的任务。
1. 无候选 → 不注入；首轮出现任务陈述则创建新任务。
2. 有候选且当前 git 分支 == 某任务 `branch` → **直接接续**，不问，注入其 `goal / open / next`（≤300 token）。
3. 有候选但分支不同或非 git → 注入一行："上次在此 repo 的任务：<goal>（<last_active>）。继续说'继续'，否则视为新任务。" 用户首轮 prompt 含"继续/接着/continue"或与 `goal` 相似度 ≥0.5 → 接续；否则创建新任务，旧任务 `paused`。
4. 多个候选 → 取分支匹配者；无分支匹配取相似度最高且 ≥0.5，否则按 3 提示最近的一个。
5. 每会话最多问一次。

**会话末：** 更新 `done / open / next / touched_paths / last_active / sessions`。

**完成：** 用户明确说完成、或 `branch` 已合并到默认分支（`git branch --merged`）、或 30 天无活动 → `task_status=done`（30 天无活动为 `abandoned`）。完成时 Reconciler 扫 `done/open`，可沉淀的决策/坑/模块知识按 §3.4 条件提炼进 L3；任务本体归档不再注入。

**不做：** 细粒度 todo、替代宿主任务列表。

## 4. 注入与召回

### 4.1 M1 基线（无学习）

| 时机 | 内容与顺序 | 预算 |
|---|---|---|
| `SessionStart` | ① L4 活跃任务摘要（若接续）② L2 生效 convention（active, `confidence≥0.5`，confidence 降序，≤12 条）③ L1 profile + 每 dimension 最具体 scope 一条 taste ④ L3 gotcha（`trigger_paths` 与 cwd 或最近修改文件命中，≤3 条）⑤ 待确认提示一行 | ≤2000 token |
| `UserPromptSubmit` | L3 语义召回 top-3（decision / map / gotcha，相似度 ≥0.5）+ L2 correction top-3（≥0.6，"上次你在类似情况下纠正过"） | ≤600 token |
| `PreToolUse`（Edit/Write，Claude Code） | 目标路径命中 `dev_gotcha.trigger_paths` → 一行提示；M2 起叠加 Compliance | ≤150 token |

格式复用上游 `<memory uri type score detail>` 信封（`render.py`），加 `layer / scope / confidence` 属性。

**排除：** `pending_confirm`、`superseded`、`retired` 不注入；跨 repo 的 `repo-*` / `glob-*` 不注入；L5/L6 在 M1 不注入；`origin=coldstart` 的 map 只在 UserPromptSubmit 语义召回时出现，不进 SessionStart。

### 4.2 M3 学习策略（P3）

- 信号：`record_used`（上游 `/sessions/{id}/used`，正）、最终产出引用了记忆 URI（正）、注入但本轮产出违反（负，M2）、注入后用户纠正了同 key（强负）、L6 experiences 中与本用户/repo 相关的成功轨迹（弱正）。
- 参数：每 (用户, layer, type, scope 层级) 一个注入权重 `w ∈ [0,2]`，初值 1；`w ← w + η·reward`，η=0.05，每周向 1 回归 10%。
- 排序分 = `confidence × w × scope_specificity(glob 1.2 / repo 1.0 / global 0.8)`；预算内贪心。
- 每次注入写 trace（§7.4）。上游 `hotness_alpha` 保持默认。

## 7. 组件与接口

### 7.1 进程

- `sagactl daemon`：`127.0.0.1:37780`，AsyncIO；上游插件 hook 通过 ≤50 行自写 shim（Apache-2.0，不复制上游 AGPL `.mjs`）POST 事件；fail-open，超时 800ms。
- 依赖 OpenViking HTTP：`/search/find`、`/search/recall`、`/content/read`、`/content/write`、`/content/batch-write`、`/sessions/*`；M4 加 ACL 接口。MCP 非必需。

### 7.2 内部 API

| 方法 | 用途 |
|---|---|
| `POST /events` | hook 事件入口 |
| `POST /recall` | 返回本轮注入块 + trace_id |
| `POST /reconcile` | 手动触发对账（调试 / `sagactl sync`） |
| `POST /check` | Compliance（M2） |
| `GET /pending` / `POST /pending/{id}/resolve` | 待确认队列 |
| `GET /tasks` / `POST /tasks/{id}` | 任务查看与状态修改 |
| `GET /trace/{id}` | 注入分解 |

### 7.3 CLI

`sagactl doctor | status | review | show <uri|topic> | explain <trace_id> | tasks [done <id>] | forget <uri|scope|session> | sync | coldstart [--from-resource] | team publish <uri> | export | bench run <config>`

### 7.4 Trace（JSONL）

recall 一行：`{trace_id, session_id, source_agent, scope_set, injected:[{uri, layer, type, scope, confidence, w, specificity, score, tokens}], excluded:[{uri, reason}], budget, latency_ms}`。
reconcile 一行：`{session_id, anchors:[uri], candidates:n, deltas:[{uri, relation, layer, type, anchor_uri, confidence_before, confidence_after}], pending:n, latency_ms}`。

### 7.5 数据位置

- 记忆本体：`viking://user/{uid}/memories/dev/{profile.md, taste/**, convention/**, correction/**, project/**, task/**}`
- 团队层：`viking://resources/sagacontext/team/{repo_key}/**`
- 本地：`~/.sagacontext/{templates/memory/, pending.jsonl, weights.json, buffer/, traces/, bench/, repo_keys.json}`
- 删除：`forget` 同时删 OpenViking 文件与本地状态；`reset` 清空 `memories/dev`；团队层只能由 `manage` 权限者删。

## 8. 隐私、许可证、故障

- `quote` 与 `symptom` 写入前脱敏（复用上游插件 secret 模式 + 自有规则），上限 160 字。
- 记忆正文视为不可信；注入信封防伪造。
- 团队层发布前弹出预览并二次确认；默认不发布 `dev_correction` 与 `dev_taste`。
- 许可证：OpenViking AGPL 独立进程；SagaContext Apache-2.0；不 vendoring 上游 `.mjs`。
- 故障：OpenViking 不可用 → 不注入，候选留在本地缓冲重试；判定模型失败 → 只保留 L0/L1 候选，不创建 upsert 类型记忆；Compliance 执行器异常 → 视为通过并记 trace；对账写回超时 → 下次 SessionStart 补写。
