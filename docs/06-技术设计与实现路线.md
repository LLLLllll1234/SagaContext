## 0. 技术目标与硬约束

**目标：** 一个本机常驻的 Python daemon + 两个宿主（Claude Code / Codex）的薄 hook 接入，在 OpenViking 之上实现六层记忆的召回、对账、写回、遵守与评测。

**硬约束（来自源码核对，决定了选型）：**

| 事实 | 出处 | 后果 |
|---|---|---|
| OpenViking 整个 Python 包（含 `openviking_cli`）与 `examples/*-memory-plugin` 均为 AGPL-3.0 | `pyproject.toml:20`、`agent-plugins/plugin.json` | SagaContext（Apache-2.0）**不能 import 任何 openviking 模块，不能复用 `.mjs`**；只走 HTTP |
| 服务端无独立 embedding 端点 | `server/routers/` 无 embed 路由 | 两两相似度（去重、任务接续）要自备 embedding |
| 记忆文件 = Markdown + `<!-- MEMORY_FIELDS {json} -->`，含 `version` | `memory_file_utils.py` | 可直接 `/content/write` 落盘，需自实现 merge_op 与乐观并发 |
| Claude Code / Codex hook 均在 stdin 给 `session_id / cwd / transcript_path`，transcript 为 JSONL | `examples/{claude-code,codex}-memory-plugin/scripts/auto-capture.mjs` | 对账直接读 transcript 文件，不依赖上游 session 消息 |
| 上游 Claude Code 插件以 `hooks/hooks.json` 形式注册，`Stop` 用 `auto-capture.mjs` 做阈值 commit | `examples/claude-code-memory-plugin/hooks/hooks.json` | 我们同样以 plugin 形式发布，与上游插件**并存**，不修改其配置 |
| 服务端默认不自动 commit，commit 全由客户端触发 | `16-capability-reference.md §2.3` | 我们的写回时机自算，不依赖观测上游 commit（关闭 v0.2 VERIFY-4） |

## 1. 总体架构

```
┌──────────────── 宿主进程（Claude Code / Codex） ────────────────┐
│  hooks.json → sagactl-hook (sh+curl, ≤30 行, fail-open, 800ms) │
└───────────────────────────┬──────────────────────────────────┘
                            │ POST /events  (stdin 原样透传)
                            ▼
┌──────────────── sagacontext-daemon (Python 3.11, asyncio) ─────┐
│  api/         FastAPI: /events /recall /reconcile /check /pending /tasks /trace
│  hosts/       claude_code.py  codex.py   ← 事件归一化 + transcript 解析
│  recall/      scope.py  policy.py  render.py        ← 锚点集 A、注入块
│  capture/     rules_l0.py  revert_l1.py  buffer.py  ← 候选缓冲（只读阶段）
│  reconcile/   anchor.py  judge_l2.py  router.py  evolution.py  writer.py
│  memory/      ov_client.py(httpx)  memfile.py(MEMORY_FIELDS)  merge_op.py  types/*.yaml
│  tasks/       lifecycle.py                          ← 任务接续
│  compliance/  compiler.py  exec_path.py  exec_pattern.py  exec_command.py   (M2)
│  learn/       weights.py                            (M3)
│  team/        publisher.py  acl.py                  (M4)
│  llm/         provider.py(OpenAI-compatible / Anthropic)  embed.py  schema.py
│  store/       sqlite.py (buffer, pending, tasks index, weights, traces, repo_keys)
│  cli/         typer: doctor status review show explain tasks forget sync coldstart team bench
└─────────────────────┬──────────────────────────────┬────────────┘
                      │ HTTP /content /search /sessions │ HTTP (OpenAI-compatible)
                      ▼                                ▼
             OpenViking sidecar (AGPL, 独立进程)   LLM / embedding provider
```

数据流两条：
- **读路径（会话中）：** hook → `/events` → `recall/` 调 OV `/search/find`（`target_directories` 限定 `memories/dev/**`）→ 组装注入块 → 以宿主 hook JSON 格式回 stdout。同时 `capture/` 做 L0/L1 检测，候选写 SQLite buffer。
- **写路径（会话末）：** `Stop/SessionEnd/PreCompact` → 读 transcript 增量 → `reconcile/` 取锚点集 + 候选 → 一次 LLM 判定 → 演化状态机 → `memory/writer` 按 MEMORY_FIELDS 格式 `/content/write` → trace。

## 2. 技术方向决策（TD-xx）

### TD-01 语言与运行时：Python 3.11+，asyncio，FastAPI + uvicorn

- **背景：** OpenViking 是 Python；判定/评测都要调 LLM；schema 用 pydantic 最顺手。
- **决定：** daemon 用 Python 3.11+；HTTP 层 FastAPI（pydantic 模型复用到 LLM 结构化输出 schema）；单进程 asyncio，不引入 Celery/队列。
- **备选：** Node/TS（与宿主插件同栈，但 LLM/评测生态弱）；Rust（性能过剩，迭代慢）。
- **代价：** 冷启动慢，所以 daemon 必须常驻；由 shim 负责"daemon 没起就拉起"。

### TD-02 hook shim：POSIX sh + curl，stdin 原样透传，fail-open

- **决定：** 每个 hook 事件一条命令：`sagactl-hook <host> <event>`，本质是
  `curl -s -m 0.8 -X POST --data-binary @- "http://127.0.0.1:37780/events?host=$1&event=$2" || true`，
  daemon 的响应原样写 stdout（即宿主期望的 hook JSON）。daemon 不在线时输出空、exit 0，并后台 `nohup sagacontext-daemon &`。
- **备选：** Node 脚本（上游做法，但 AGPL 不可复用且要装 node）；Python 脚本（冷启动 60–100ms × 每轮多次 hook）。
- **代价：** shim 里不能做任何解析；所有宿主差异在 daemon `hosts/` 层处理。Windows 暂不支持（M4 再议）。

### TD-03 以 Claude Code plugin 形式发布，与上游 OpenViking 插件并存

- **决定：** `plugins/claude-code/{plugin.json, hooks/hooks.json}` 注册 `SessionStart / UserPromptSubmit / PreToolUse(Edit|Write|MultiEdit) / PostToolUse(Edit|Write|MultiEdit|Bash) / Stop / SessionEnd / PreCompact`；Codex 侧按上游 codex-memory-plugin 的 4 事件写 `hooks` 配置，由 `sagactl install` 写入。不改上游插件配置。
- **重复注入风险：** 上游插件 SessionStart 会注入 `profile.md` + preferences 索引；我们只召回 `memories/dev/**`，两者不重叠。若用户没装上游插件，SagaContext 仍可独立工作（它只依赖 OV 服务端）。
- **备选：** fork 上游插件加功能（AGPL 传染 + 维护分叉）；要求用户卸载上游插件（损失通用记忆）。

### TD-04 OpenViking 访问：自写 httpx 客户端，只用 HTTP API

- **决定：** `memory/ov_client.py` 封装 `/api/v1/content/{read,write,batch-write,delete}`、`/search/{find,recall}`、`/sessions/{id}/used`、M4 加 `/acl/*`。鉴权与 base_url 读 `ov.conf` / 环境变量（与上游插件同源，避免双份配置）。
- **备选：** import `openviking_cli` SDK（AGPL，否）；MCP（多一层进程，且不必需）。
- **代价：** 上游 API 变更要自己跟；用 `tests/contract/` 录制的响应做契约测试，升级 OV 时先跑。

### TD-05 记忆写入：直接落盘 MEMORY_FIELDS 格式，客户端实现 merge_op + 乐观并发

- **决定：** `memfile.py` 负责 Markdown 正文渲染 + `MEMORY_FIELDS` JSON（含 `version`）序列化/解析；`merge_op.py` 实现 `patch / replace / sum / immutable` 与上游同语义（patch 是 SEARCH/REPLACE，但我们由 Reconciler 直接给出新值，客户端做 diff → SEARCH/REPLACE 只为保持文件可被上游 `remember` 路径继续 patch）。写前 `content/read` 取 `version`，写后若 `version` 非预期 +1 则重读重放（最多 3 次）。
- **备选：** 走上游 `remember` / session commit 让服务端抽取（丢证据、无法锚定）。
- **代价：** VERIFY-1 若发现直接写入的文件不参与 recall 分类，退路是：写入后再调一次上游的 semantic refresh（`/content/write` 有 `processing_mode` 参数，先用它）。

### TD-06 本地状态：单文件 SQLite（WAL），JSONL 只作导出格式

- **背景：** 多个宿主会话并发触发 hook；v0.2 写的 `pending.jsonl / buffer/*.jsonl / weights.json` 在并发追加下会损坏。
- **决定：** `~/.sagacontext/state.db`，表：`buffer / pending / tasks / weights / traces / repo_keys / sessions`。`sagactl export` 输出 JSONL。**此处修订 04 v0.2 §7.5，v0.3 同步。**
- **备选：** 每会话一个 jsonl（读取要扫目录，跨会话查询难）；Redis（多一个进程）。

### TD-07 判定模型：OpenAI-compatible + Anthropic 两种 provider，结构化输出 = JSON schema + pydantic 校验 + 一次重试

- **决定：** `llm/provider.py` 只支持两类协议；默认 provider 从 `ov.conf` 的 `[vlm]` / `[query_planner]` 段推导（04 v0.2 §10 决议 6），`~/.sagacontext/config.toml` 的 `[llm]` 可覆盖。输出 schema 由 pydantic 模型生成；解析失败重试一次并降低温度；再失败则本次对账只保留 L0/L1 候选、不创建 upsert 记忆（04 §8 故障策略）。
- **备选：** litellm（依赖重、抽象层多）；本地小模型（M1 不做，接口留着）。
- **成本控制：** 一次对账一次调用（transcript 摘要 + 锚点 + 候选一起给），不逐候选调用；transcript 超预算先做确定性压缩（去 tool 输出、保留 user turn 与 Agent 声明的修改）。

### TD-08 相似度：检索用 OV `/search/find` 的分数，两两相似度自备 embedding，无 embedding 时退化为词法

- **决定：** 锚点召回、语义召回全部用 OV 打分，不重造检索。去重（≥0.85）、任务接续（≥0.5）、锚点排序里的相似度用 `llm/embed.py`：优先与 OV 相同的 embedding provider（读 `ov.conf [embedding]`，OpenAI-compatible），不可用时退化为 `rapidfuzz` 词法相似度（阈值另配，标 `[TARGET]`）。
- **备选：** 本地 onnx 小模型（fastembed）——留作可选依赖 `sagacontext[local-embed]`，M1 不默认装。
- **代价：** 词法退化路径下去重质量下降；trace 里记录用了哪条路径，评测时分开统计。

### TD-09 transcript 解析：宿主适配器把两种 JSONL 归一成同一 `Turn` 模型，增量游标存 SQLite

- **决定：** `hosts/claude_code.py` / `hosts/codex.py` 各自解析 JSONL 为 `Turn{idx, role, text, tool_calls[{id,name,input,output_digest}], ts}`；按 `(session_id, byte_offset)` 存游标，Stop 只读增量。grounding 的 `turn_range` 用归一化后的 `idx`。
- **备选：** 用上游 session 消息（要先 commit，且 tool 输出被外置/截断）。
- **代价：** 两种格式各需一套 fixture 与回归测试；宿主升级可能改格式，用 `tests/fixtures/transcripts/` 锁住。

### TD-10 revert 检测（L1）：PostToolUse 记 Edit 后文件内容哈希，下一 user turn 前比对工作树

- **决定：** Claude Code：`PostToolUse(Edit|Write|MultiEdit)` 记 `(path, sha256(after))`；`UserPromptSubmit` 时对比当前文件哈希，不同且 `git diff` 显示与 Agent 改动方向相反 → `revert_and_redo` 候选。Codex：无 PostToolUse，Stop 时用 transcript 中 Agent 声明改动的文件 vs `git diff --stat`。
- **代价：** 非 git 目录只能做哈希不等判断，标低置信 0.5。

### TD-11 对账引擎：纯函数管线 + 录制回放测试

- **决定：** `reconcile/` 的每一步都是 `(inputs) -> outputs` 的纯函数：`select_anchors(A_all, session_summary) -> A`、`judge(A, C, transcript) -> deltas`（唯一有副作用的是 LLM 调用，可注入 mock）、`route(deltas) -> typed_ops`、`evolve(existing, op) -> new_state`、`plan_writes(...) -> [WriteOp]`。LLM 调用与写入的真实请求/响应用 `tests/recordings/` 录制回放（vcr 风格）。
- **原因：** 锚定命中率、重复记忆率这些指标要能离线复算；改 prompt 后能直接跑回归。

### TD-12 Compliance 执行器（M2）：PreToolUse 返回宿主 hook JSON；pattern 用正则，AST 留接口

- **决定：** `path` 与 `pattern` 在 `PreToolUse` 同步执行（预算 150ms），返回 `{"decision":"block"|"approve", "reason": ...}`（Claude Code 格式；Codex 无 PreToolUse 退化为 Stop 软强制）。`pattern` 只做正则；tree-sitter 作可选依赖 `sagacontext[ast]`，M2 后半段再评估。`command` 在 Stop 异步跑，结果通过下一轮注入。
- **代价：** 正则误杀率要靠 `block 误杀率 <5%` 指标兜底；默认 `warn`。

### TD-13 评测框架：自建轻量 runner，驱动 `claude -p` / `codex exec`，判定 = 确定性检查优先、LLM judge 兜底

- **决定：** `bench/` 独立子包：`cases/*.yaml`（场景、T1/T2/T3 会话脚本、GT）、`runners/{claude_code,codex}.py`（headless 起会话）、`judges/{deterministic,llm}.py`、`report.py`（JSONL → Markdown 表）。遵守率/误注入率/任务接续用确定性检查（grep、路径、结构比对）；事实回忆、演化正确率用 LLM judge 并抽 20% 人工复核。基线系统各写一个 `adapters/<name>.py`（安装/清空/注入方式）。
- **备选：** 接 LongMemEval/LoCoMo 框架（域不对，02 §4 已否）；用 promptfoo（对多轮会话 + 宿主进程支持弱）。

### TD-14 打包与安装：`uv` 管理，`pipx install sagacontext`，`sagactl install` 一键写配置

- **决定：** `pyproject.toml` + `uv.lock`；可选 extras：`[local-embed]`、`[ast]`、`[bench]`。`sagactl install` 做四件事：写 `ov.conf [memory].custom_templates_dir`、复制 8 个 yaml 模板、注册 Claude Code plugin / 写 Codex hooks、装 launchd/systemd user 服务（daemon 常驻）。`sagactl doctor` 验证每一项。
- **代价：** 需要 OV 服务端重载模板（确认 registry 是否热加载，否则提示重启 OV）。

### TD-15 可观测性：structlog JSON 日志 + SQLite trace + `sagactl explain`

- **决定：** 每次 recall / reconcile 一条 trace（04 v0.2 §7.4 结构）；日志按天滚动 7 天；`explain <trace_id>` 打印每条注入/增量的四个因子与锚点。不接 Prometheus（M4 视情况）。

### TD-16 安全边界

- daemon 只绑 `127.0.0.1`，无鉴权（同上游插件假设：本机单用户）；M4 加可选 token。
- 记忆正文按不可信处理：注入前转义 `<memory>` 信封中的尖括号；`quote / symptom` 写入前过 secret 规则（正则集合：API key、token、私钥头、`.env` 行）。
- 团队层发布必须经 `sagactl team publish` 显式确认，daemon 不会自动向 `viking://resources` 写。

## 3. 关键模块设计要点

### 3.1 事件归一化（`hosts/`）

```python
class HostEvent(BaseModel):
    host: Literal["claude-code", "codex"]
    event: Literal["session_start","prompt","pre_tool","post_tool","stop","session_end","pre_compact"]
    session_id: str
    cwd: Path
    transcript_path: Path | None
    prompt: str | None                 # prompt 事件
    tool: ToolCall | None              # pre/post_tool
    raw: dict                          # 原 payload，仅落日志
```

`hosts/*.py` 只做字段映射与 transcript 解析；所有业务逻辑不感知宿主。

### 3.2 scope 解析（`recall/scope.py`）

`repo_key(cwd)`：`git rev-list --max-parents=0 HEAD | head -1` → sha1[:8]，缓存到 `repo_keys(realpath, key, kind)`；非 git → `path` kind。当前编辑文件来自 `pre_tool/post_tool` 的路径或 prompt 中的路径提及（简单正则），用于 glob scope 命中。

### 3.3 锚点集选择（`reconcile/anchor.py`）

输入：本会话所有 recall 返回过的 URI（已在 trace 里）∪ 用会话摘要再查一次 `/search/find`（`target_directories=[memories/dev/**]`, limit 60）。排序分 = `specificity(glob 1.2 / repo 1.0 / global 0.8) × ov_score`；每个出现的 type 保底 2 条；前 20 条读全文（`content/batch-read` 若有，否则并发 `content/read`），其余只带 URI + `abstract`。

### 3.4 判定输出模型（`reconcile/judge_l2.py`）

```python
class Delta(BaseModel):
    layer: Literal["user","preference","project","task"]
    type: Literal["dev_profile","dev_taste","dev_convention","dev_correction",
                  "dev_decision","dev_project_map","dev_gotcha","dev_task"]
    relation: Literal["confirm","refine","supersede","new","conflict"]
    anchor_uri: str | None             # relation != new 时必填
    key: str                           # topic / component / dimension / task_id
    scope: Scope
    fields: dict[str, str | int | float]
    grounding: Grounding
    strong_signal: bool                # "以后都" / 明确陈述 → supersede 直接生效
    confidence_hint: float
```

二次校验：`relation == "new"` 且与同 type 锚点 embedding 相似度 ≥0.85 → 改判 `refine`，并写入 `pending_review_sample` 供人工抽检（锚定命中率数据来源）。

### 3.5 写计划（`reconcile/writer.py`）

每条 `Delta` → 0..n 个 `WriteOp{uri, mode: create|patch|replace, fields_after, expected_version}`。`supersede` 生成两个 op（旧文件改 `status/superseded_by`，新文件 create）。批量用 `/content/batch-write`；失败按 op 粒度重试；全部完成后写 reconcile trace。

### 3.6 注入渲染（`recall/render.py`）

沿上游 `<memory uri="…" type="…" score="…" layer="…" scope="…" confidence="…">正文</memory>` 信封；正文只放 `rule / decision / symptom+fix / goal+open+next` 等"可执行"字段，不放 evidence。预算按 04 v0.2 §4.1，用 tiktoken 估算。

## 4. 实现路线

原则：**每一步都是可演示的竖切**，先打通"记一条、取回来"，再加智能。数字为工作量估计，不是承诺。

### Phase 0 · Spike 与验证（1 周）

| 项 | 产出 | 关闭的验证项 |
|---|---|---|
| 起本地 OV（docker-compose），装上游 Claude Code 插件 | 可复现的开发环境脚本 `dev/up.sh` | — |
| 手写一个 `dev_convention` 文件用 `/content/write` 写入，跑 `/search/recall` | 分类/分数/`record_used` 行为记录 | VERIFY-1 |
| 自定义 yaml 多级 `filename_template` 走 `remember` 一次 | 目录结构截图 | VERIFY-3 |
| 两用户两 group 在 `viking://resources/sagacontext/team/` 写读 | ACL 行为记录 | VERIFY-2 |
| 读 Claude Code 与 Codex 的 transcript JSONL 各 3 份，写 fixture | `tests/fixtures/transcripts/` | TD-09 前提 |
| 写 sh shim + 最小 FastAPI `/events` 回 echo | hook 往返延迟测量 | TD-02 |

**退出条件：** VERIFY-1 为"是"或找到 `processing_mode` 退路；shim 往返 p95 < 100ms。

### Phase 1 · M1 本体（6–8 周，四个竖切）

**Slice A · 记一条取回来（1.5 周）**
`memory/{ov_client,memfile,merge_op}` + 8 个 yaml + `recall/{scope,policy,render}` + `hosts/claude_code` + `SessionStart/UserPromptSubmit` 注入 + `sagactl install/doctor/show`。
演示：手工 `sagactl add convention …`，新会话开头能看到它，换 repo 看不到。

**Slice B · 纠正挖掘与对账（2 周）**
`capture/{rules_l0,revert_l1,buffer}` + `store/sqlite` + `reconcile/*`（锚定抽取、演化状态机、写计划）+ `Stop/SessionEnd/PreCompact` 写回 + `pending` 队列 + `sagactl review/explain`。
演示：会话里说两次"别用 any"，下次会话开头出现 `ts_no_any`；再说"以后可以用 any"，旧条 superseded。

**Slice C · 项目层与任务层（2 周）**

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| VERIFY-1 为否：直接写入不参与 recall 分类 | 读路径失效 | Phase 0 就测；退路 `processing_mode` 强制 semantic 处理，再退路是写后调 `remember` 触发一次空 commit |
| 上游 HTTP API 变动 | 客户端断 | 契约测试 + 锁定 OV 版本区间；`doctor` 检查 OV 版本 |
| 宿主 transcript 格式变动 | 对账失效 | fixture 回归 + 解析失败时降级为"只用 hook payload 里的 prompt/tool 字段" |
| LLM 判定成本 | 每次对账一次调用，长会话输入大 | 确定性压缩 + 12000 token 上限 + 阈值触发而非每轮 |
| 与上游插件重复注入 | token 浪费 | 只召回 `memories/dev/**`；`doctor` 检测上游插件是否也注入 dev 目录 |
| 正则 block 误杀 | 用户关掉功能 | 默认 warn；误杀率指标；连续 3 次"这次就这样"自动降级 |
| Windows | 无 sh/curl 假设 | M4 前不支持，README 注明 |
